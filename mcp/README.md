# mcp/

MCP server 服务端。承载两类东西:

- workflow:流程规范的可执行形式——写路径审批、预设执行器、卡点状态机。它与 skill 平级,是一等资产;实现在服务端而非引擎 plugin,因为要跨引擎、可强制、可测试。
- 数据工具:把现有只读脚本(psm_overview 等)包成 MCP 工具,供需要这些能力的会话按需调用。

护栏下沉原则:能放进工具服务端的逻辑(dry_run 默认、权限校验、审计)不放进引擎 plugin。写生产的最终闸门在生产侧执行通道,这里的审批 workflow 是它的前置环节。

尚无内容,且刻意推迟(2026-06-11 决策):只读工具经 bash 白名单已可用,本地 stdio MCP 不提供任何强制力增量,不为 MCP 而 MCP。触发条件三选一,谁先到做谁:

1. 第一个写动作进场(必须,且必须是服务端部署形态:审批 / dry_run 强制 / 审计 / 凭证隔离);
2. chat 态寄生 AIME/Mira(自定义助理挂工具仅支持 MCP);
3. 工具参数复杂度或结构化遥测需求越线(schema 才值回票价)。

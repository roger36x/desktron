# 来源权威度（DocAuthority）：按源信任校准

> 质量两轴(confidence 真值 + authority 来源权重;原 completeness 已退役)见 curator `SCHEMA.md`「质量两轴」与 `README.md`:authority 由 curator 用 graph 信号算、外部源走实例插件,结构信号共享、使用热度落消费方本地。本文保留 authority 的合成原则与结构,机制以 curator docs 为准。

> authority ≠ confidence。权威度是**候选来源之间的软排序权重**（先读谁、谁的话权重高），不是单条信息的置信度。authority 再高也只有一个来源，仍是 `documented`；顶档 `corroborated` 要两个及以上独立来源。两者别混。

## 用途

调研时手上有一堆候选来源，要决定先信谁、先读谁、用谁印证。给每个来源一个 0–1 的权重做排序。它**不**改这条信息的 confidence——confidence 按 source 里有几个独立来源定（0 / 1 / ≥2），与来源本身的权重无关。

## 打分（合成结构搬 workbench，信号源要重定）

workbench 的合成形态（机制可搬）：

```
score = 标题类别先验 × 新鲜度 × (0.5 + 0.3 × 读者广度 + 0.2 × 讨论量)
```

四个信号：

- **标题类别先验**　[验证]　按文档类别给基础权重（如"规范/标准" > "个人笔记" > "草稿"）。类别表由领域定义。
- **新鲜度**　[验证]　`0.5^(age / 半衰期)`。workbench 用半衰期 365 天。越旧权重越低，但不归零（旧不等于错）。
- **读者广度（uv）**　[待验证]　workbench 取飞书文档的访问 uv。Desk 工作区记忆、DeepWiki 与普通 git 仓没有 uv 这种信号，要么换等价信号（如被多少条记忆 `[[link]]` 引用 = 内部读者广度），要么置中性值 0.5。
- **讨论量**　[待验证]　workbench 取评论数。desktron 同样缺，换等价（如 git 提交热度 / 被引次数）或置中性。

## desktron 的落地姿态　[待验证]

- 可直接用的：标题类别先验、新鲜度（`last_verified` 已有）。
- 缺信号源的：读者广度、讨论量——不要硬套飞书那套，先用"被 `[[link]]` 引用次数"近似，或整体降为"类别先验 × 新鲜度"两信号版，等真实信号源确定再补。
- 不预先建脚本：和 sot 一样，等"候选来源排序"成为真实痛点再落可执行版；现在先把原则和合成结构写下来，调研时人/agent 心里有这杆秤即可。

## 反模式

- 把 authority 当 confidence：来源权威 ≠ 这条就对。
- 单一高权威来源即采信：仍要交叉验证。
- 某人的输出按其修辞强度加权：authority 是**来源/文档**的权重，不是给具名个人的话加 buff——对人的信任校准（"某人的评价按其陈述打折"）属 journal，不进这里。

# kb-review

用于在说明文档进入 Git 历史前做最后检查。

## 检查内容

1. **内容是否合适**：只保留可核实的陈述；操作步骤应放入对应说明，项目判断应留在项目记忆中。
2. **位置是否正确**：Desk 产品说明放入对应的 `desk-docs/` 或 `docs/`；业务专属内容留在业务自己的正式来源；只对当前用户有效的内容不进入 Git。
3. **依据是否充分**：逐条确认来源能直接支持正文。来源不可取得、已经过期或只支持部分内容时，缩小表述并说明缺口。
4. **是否重复**：与现有文档和目标来源比较。内容相同时，优先更新已有的正式条目。
5. **是否包含敏感信息**：凭证、身份标识、具名个人评价和合规敏感内容必须先删除或改写。

## 输出

```text
检查对象：<文件或条目>
事实依据：通过 / 问题
存放位置：通过 / 调整建议
重复内容：无 / 已有条目
敏感信息：无 / 需处理
结论：可以提交评审 / 先修改
```

本说明不执行 commit、push、MR、发布或记忆写入。

# App Control

Desk's Runtime enforces leases, permissions, idempotency, and receipts. Use the `app-control` CLI; do not call `/host/*` endpoints, inject arbitrary JavaScript, or try to obtain the host token.

## Two ways to get a page

**Open a page yourself (the default choice).** `app-control open <url>` opens an isolated tab directly and holds it, with no button for the user to press. That tab uses separate storage, without the user's cookies or intranet SSO, so it can do no more than a freshly installed browser. Use this for public research, reading documentation, and filling in public forms.

Only `app-control open <url> --with-identity` uses the user's login state (needed for intranet sites). The first time, Desk shows a confirmation dialog to the user; once approved, the site is remembered for a day and later tabs on the same site are not asked about one by one. The list of authorized sites is not exposed to the Agent; the user views and revokes it in Desk settings. Without authorization, do not retry repeatedly, and do not switch to an isolated tab to get around a login wall.

**Take over the user's page.** When the user has a page open and wants you to work on it, they press "Hand to Agent", and then you run `app-control claim`. What this guards is not "operating a web page" but "operating a web page as the user", so a person must initiate it.

## Procedure

1. Confirm the app and actions are available with `app-control list`; see the tabs this session holds with `app-control tabs`.
2. Open your own page with `app-control open`; to take over a page the user already has open, wait for them to press "Hand to Agent", then run `app-control claim`. If told there is no delegation, stop and ask the user to press the button.
3. Read the structured page with `app-control inspect document`. It returns a parent-child node tree with role, name, states, state_sources, selected_values, frame_id, and the modal/menu/popover stack. The tree includes body structure: paragraphs, lists, tables, sections, captions, and code blocks each have their own nodes and roles; canvas, svg, video, audio, and iframe also enter the tree with size and position, and seeing them means that content cannot be read, so switch to a screenshot. The top-level `text` field keeps the original page's line breaks and can be read directly as body text. For large pages, `--input '{"find":"keyword"}'` returns only matches and their ancestors, `root_node_id` reads only a subtree, and `include_offscreen` also reads outside the viewport; `truncated` being true means nodes were cut off by `max_nodes`, so raise `max_nodes` or narrow with `find` / `root_node_id`. Later node actions carry the returned `observation_version`; when navigation or a redraw makes the version stale, observe again.
4. For fill, select, type, hover, scroll, and `dblclick`, `check`, `uncheck`, `focus`, `blur`, use `app-control act <action> --input '<JSON>' --expected-version <version>`. For drag-and-drop use `drag`, giving two stable targets as `source` and `target`. A target can be a `node_id` (valid within this observation), a `selector`, or a more stable `locator` (supporting `role`, `name`, `text`, `test_id`, `selector`, `exact`, and `nth`; `nth` starts at 0, and -1 is the last one). Targeted actions wait automatically for the element to be present, visible, enabled, and stable; pointer actions look for an unobscured point inside the target, and on failure return the obscuring node and candidate points, never clicking through. `fill` only changes the value without submitting; `click`, `hover`, `dblclick`, `check`, `uncheck`, `drag`, `type`, and `press` are all delivered by the host as real mouse or key events.
5. Actions that may cause external writes, such as `click`, `dblclick`, `check`, `uncheck`, `drag`, `press`, and `coordinate_click`, must carry a unique `--idempotency-key`, and use `--intent "one sentence on the purpose of this run"` to tell the user exactly what they are approving. `--intent` states the business purpose, not technical steps such as "click a page element"; it is for explanation only and does not change the permission level. The Runtime executes only after the user confirms. Use `coordinate_click` only when a structured node cannot reach the target, and always with the version from the latest inspect. Do not simulate submission with other actions.
6. Navigate with `navigate` / `back` / `forward` / `reload`; `activate` confirms the background execution target without switching the user's foreground; when a person needs to continue the original form, use `handoff`, which, after the user confirms, shows and takes over the original tab bound to the lease; do not reopen the URL. `close` closes a tab (requires confirmation). `wait` can wait for `text`, `selector`, `url` (`url_mode` equals/contains/prefix), or `network_idle`, with `timeout_ms`. Network idle waits for both the document/DOM to settle and same-origin Fetch/XHR to drain; cross-origin iframes, WebSockets, images, and font requests are not counted.
7. When an action receipt has `requires_reinspect` true, inspect again before continuing. Get the final receipt with `app-control receipt <operation_id>`; on failure, use `app-control trace <operation_id>` to see wait counts, target rectangles, obstruction hits, page ownership, and the event timeline. Traces hide typed text and form values.
8. When the work is done, return control with `app-control yield`.

Pages you open yourself run in the background by default; actions are targeted by the lease's `resource_id`, so the user does not need to switch tabs or keep Desk in front. The user can view the page from the browser tab bar. Background compatibility varies by site; flows that depend on foreground visibility or system dialogs are not guaranteed to finish in the background. When you clearly hit such an obstacle, report it and hand it to a person; do not grab the foreground automatically or bypass approval.

Take screenshots with `app-control inspect screenshot`. For isolated tabs you opened yourself (the `open` default), screenshots are at the same level as reading text and no longer need confirmation each time; tabs with identity (`--with-identity`) and pages the user handed to you still need confirmation each time. For every resource, screenshots mask password and token inputs. To show a screenshot to the user, write `![description](/workbench/view?raw=1&path=<the path from the receipt, URL-encoded>)` in the reply body; the chat area renders it inline, and clicking shows the original. `src` accepts only this local endpoint; an external link degrades into a line of link text. `--input '{"full_page":true}'` captures the whole page, and `--input '{"clip":{"x":0,"y":0,"width":800,"height":600}}'` captures part of the visible area. Structured snapshots remain the default way to observe.

For troubleshooting resource loading, use `app-control inspect network --input '{"limit":200}'`; it returns timing, type, transfer size, and protocol for same-origin page resources, keeping only origin + path in addresses and providing no query strings, request headers, or response bodies. Conditional waits can use `wait` with `selector` or `locator`, together with the states `attached / detached / visible / hidden / enabled / disabled / checked / unchecked / mixed`, and can verify selections with `value` / `values`; for multi-select boxes use `select --input '{"selector":"#team","values":["A","B"]}'`, while single selects still use `value`.

For asynchronous flows such as publishing or multi-step confirmation, add `wait_for` to the action input, with the same fields as `wait`, for example `{"selector":"#publish","wait_for":{"selector":"[role=dialog]","state":"visible","timeout_ms":10000}}`. The action is approved and executed first, then the condition is probed read-only; `action_executed:true` does not mean `condition_met:true`. Pointer receipts without a postcondition are marked `outcome:delivery_only` and `effect_verified:false`; do not claim business completion from them. On `postcondition_timeout`, query the receipt and observe again; do not click again with a new idempotency key.

For long waits, use `app-control act wait --timeout 0 --input '<condition>'` to get an operation_id immediately, then poll briefly with `app-control status <operation_id>`. The condition's `timeout_ms` is at most 1800000 (30 minutes); the Runtime probes about once a second, keeps the original deadline across restarts, and resumes only reading, never replaying write actions. Use `state:enabled` to wait for a continue button to unlock; `abort_if` gives a CSS selector for a failure message and returns `wait_aborted` when it appears; `guard_url` binds the full business page URL (including query string and hash) and returns `resource_changed` when it changes. Omit URL constraints only when navigation is clearly expected. A vanished tab, user intervention, or an invalid lease all end the wait.

## When to hand over to a person

System dialogs (alert/confirm/prompt), file pickers, and download locations are handled by the user: the host pauses the lease and marks the receipt `needs_user`, and the person returns the lease when done, but previously queued actions do not resume. First run `inspect document` again and check the URL, ticket, or publishing target before deciding the next step; `human_intervention_reinspect_required` means that re-check has not been done yet. `capabilities` and `opaque_frames` in the snapshot show which parts cannot be read (cross-origin iframes). When you meet these, stop and tell the user; do not work around them.

The lease pauses or becomes invalid after the user actually clicks, types, navigates, or takes back control; a page you opened yourself can keep running in the background when the user merely looks at it and switches away, while a paused page where a person has intervened waits for the user to switch back. On `lease_revoked`, `stale_or_missing_node`, `locator_ambiguous`, a target wait timeout, or a version conflict, stop the current action; do not work around it automatically or submit again. Operability failures are reported explicitly as not visible, disabled, unstable, or obscured, and are never forced. When the lease reports `browser_tab_unavailable`, the tab view is gone; open again or ask the user to delegate again.

## Native application windows (read only)

Apps in `app-control list` that carry `native_application` (such as `shadowrocket`) offer L1 observation only. After the user turns on the matching switch in the "Debug" section of Desk settings and selects the window in the dialog, run `app-control --app <app> claim`, then `app-control --app <app> inspect window`. It returns a `desk.native-window/v1` structure: nodes have only `ref`, `parent`, `role`, `semantic`, `enabled`, `selected`, and value tokens registered in advance in the manifest (such as `on`, `status_connected`); it contains no window title, original text, node names, subscriptions, or credentials. Information you cannot read is simply not offered; do not try screenshots, OCR, AppleScript, or coordinate clicks. The lease pauses while the user operates the window; inspect again once it is idle. The lease is revoked when the target closes, the process restarts, or its identity changes; ask the user to select the window again. Native applications offer no actions.

## Capturing reusable steps

Once a flow works, `app-control sequence capture > seq.json` exports the portable successful actions from this session (only selector/locator targets, without one-time node_ids or form values); `app-control sequence run seq.json --run-id <stable id>` replays it under the same approval and receipt rules; and `app-control sequence skill <name> seq.json` turns it into a local Skill.

When a sensitive input returns `sensitive_field_needs_user`, hand it to the user to fill in. Never request or output passwords, cookies, tokens, request headers, LocalStorage, or credential values.

# Windows 双顶栏设计

## 确认的布局

保留上下两条顶栏，但两条都只覆盖右侧主内容区；左侧仍是一层通顶侧栏。

```text
Desktron · 搜索 │ 留白拖动区 ········ ─ □ ×
               ├────────────────────────
功能入口       │ 导航 · 会话标题 · 工具
工作流与会话   ├────────────────────────
               │ 主内容区
```

- 上层为 32 逻辑像素原生窗口标题区，负责拖动和窗口控件，不绘制重复的 Desktron 品牌字。保留系统窗口名称，供任务栏、Alt+Tab 和窗口识别使用。
- 下层沿用 Desk 页头，保留导航、标题与工具。终端和会话页头最小高度为 44 像素，资产页保留原有高度。
- 左侧品牌和搜索从窗口顶部开始；不新增第二层图标栏。
- 侧栏改变宽度时，两条顶栏起点随主区左缘移动。侧栏收起或终端全屏时，两条顶栏扩展至全宽。
- 使用中性深浅主题；不新增 Mica、装饰渐变或包围内容的大圆角框。

## 原生与前端分工

`desktop/windows/src/chrome.rs` 使用独立 caption 子 HWND 绘制右侧上层。父窗口只负责材质底图；普通 GDI 的 RGB 值不保证玻璃区域不透明，因此标题先绘到 32 位 DIB，设置 alpha=255，再提交。父底图清理排除当前 caption，但不排除透明 WebView，旧标题范围仍会被清理。

tao 阴影窗口仍带 `WS_CAPTION`，整窗扩展材质时会保留系统标题绘制入口；Chrome 去掉标题样式，并在 `WM_STYLECHANGING` 防止最大化／还原重新加入，但保留 `WS_THICKFRAME`、系统菜单及最小最大化能力。不禁用整个 DWM 非客户区，不使用 NOREDIRECTIONBITMAP。窗口行为仍需验收。

tao 使用 `CS_OWNDC`；绘制以 `SaveDC/RestoreDC` 恢复应用裁剪。标题子窗口命中返回 `HTTRANSPARENT`。普通/最大化均接管 `WM_NCCALCSIZE`，以整窗为客户区，消除默认 NC 灰边及标题侧缘白边；Windows 11 继续设置 DWM border none，保留阴影和系统消息链。WebView 不再额外让出一物理像素上沿，避免纯色回退时缺少明确底色。

八向输入由独立 layered child HWND 承载：区域仅包含 DPI resize 热区，alpha=1 避免 alpha=0 的鼠标穿透，黑色仅影响至多一个色阶，不画可见色条。命中返回 resize code；缩放启动、边缘双击/右键转交顶层，系统处理光标。最大化时隐藏；尺寸/DPI 消息同步更新区域，browser/tag 事件后恢复 HWND_TOP。销毁回调清空句柄，避免先销毁顶层后 Drop 操作过期 HWND。

已排除的是**没有独立输入层的全客户区方案**：真实 WebView 子目标返回 HTCLIENT，单靠父 HWND 的正确命中不能修复被遮挡的输入。仅保留 NC 加 DWM border none 也已排除：普通 NC 绘制仍在，灰边可通过旧 <150 检查。输入层的真实拖动/光标与 Snap 仍须动作级验收。

`WM_GETMINMAXINFO` 先交给 tao 保留最小/最大拖动尺寸约束，再按当前显示器有效工作区设置最大化 OUTER 大小及相对位置。不能只将客户区裁到 rcWork 却让外窗覆盖任务栏；多显示器自动隐藏任务栏按 ABM_GETAUTOHIDEBAREX 预留一像素唤出带。

主 WebView 覆盖整个客户区，通过 `SetWindowRgn` 仅扣除右侧标题区；八向缩放层在其前方，内部区域不遮挡页面控件。标题区返回 `HTCAPTION`，最大化按钮返回 `HTMAXBUTTON`。按钮发送系统命令，关闭经 `SC_CLOSE` 到达既有 `CloseRequested` 与回合保护，不直接结束进程。

`desktop/windows/js/window-chrome.js` 仅在本机工作台主框架启用 `desk-windows-chrome`，观察主区尺寸和侧栏开合，上报左缘。原生接收有限数值后更新裁剪；失败记录固定错误，不静默退回旧外观。

`frontend/window-chrome.css` 只对该能力标记生效，为主区预留上层高度，将页面导航移入下层并为标题避让。macOS、普通浏览器和旧 Windows 壳不启用新布局。

## 排除的做法

- 不保留默认跨窗系统标题栏：无法让它直接避开左侧栏。
- 不只画三个 HTML 窗口按钮：不能由此保证原生命中测试和吸附布局。
- 不复用 macOS 的 `fullsize-shell`：其中包含左侧红绿灯偏移。
- 不继续采用单行融合方案：用户最终确认保留双顶栏。
- 不将源码编译、坐标单测或 HTML 预览当作已部署及真机验收。

## 历史验证与交付记录

以下按修复先后保留证据。最终候选的已有记录见本节末尾：整体视觉问题已获用户确认；这不替代尚未完成的专项验收。

用户安装后曾出现全宽空白条及页头缺失；修复文档创建时根节点为空和绘制顺序后，用户确认双顶栏与通顶侧栏恢复。随后用户报告最大化时右上区域变黑，普通窗口正常，并要求去掉上层品牌字。

当前源码移除上层品牌字，并修复跨帧 DC 裁剪累积。格式检查、Clippy 无告警、离线 release 构建及 4 项 Rust 测试通过；新增内存 GDI 测试复现旧裁剪挡住新增右缘，并验证放大/还原和侧栏收起后裁剪恢复，不创建真实窗口。

3 个后台回归文件共 55 项通过、6 项跳过。此证据不代表新壳已安装或最大化画面验收通过。

HTML Demo 是自包含的外观示意，窗口按钮只模拟反馈，不操作真实窗口或请求模型。

## 原验收清单与后续结果

以下是当时制定的验收范围，不表示全部仍待执行，也不表示均已通过。最终记录后仍未专项验收的项目单列于末尾；新的安装或重启须独立授权：

1. 深浅主题、普通窗口、最大化、失焦、长标题和最小尺寸。
2. 侧栏开合、宽度拖动、终端全屏、设置与应用页面。
3. 标题拖动、双击、八向缩放、最小化、最大化/还原、关闭确认、系统菜单和 Win+方向键。
4. Windows 11 最大化按钮悬停的 Snap Layouts；仅有 `HTMAXBUTTON` 源码不足以证明可用。
5. 跨不同 DPI 显示器拖动；浏览器原生视图、浮动标签与设置遮挡。
6. 原生宿主身份、后端监督、退出及重开恢复。

# Shepherd 切换、投递与退出边界

本文档从”跨引擎往返切换后无法发送”的故障出发，在现有编码器、串行锁、Manifest 和恢复栅栏上补齐边界，不引入通用事务框架。

## 已实现

- 三引擎 Connector 必须实现只读 `preflight(rounds, checkpoint, checkpoint_meta)`。新切换在撤销原 Producer 之前调用。已有 pending switch 继续在原恢复路径预检和追平，不复活旧 Producer。预检复用目标编码器，避免另一套格式规则。
- Codex 与 Claude 补充了工具调用和结果类型的配对检查。Codex 拒绝非字符串 custom tool 输入及重复调用 ID。
- 后台引擎准备失败时即时显示持久化警告，不等下一次发送才报告。过期选择的错误不覆盖新选择，成功或改选清除本类警告，不清除其他恢复提示。
- 三引擎待发消息统一在权威 ready 后续发。重启或中断导致回执丢失时只触发状态核对，不要求用户解除暂停。执行结果未知时仍服从后端恢复栅栏，禁止重放。
- 临时发送错误先查询持久回执。只有本次 `cancel-unsent` 成功封住未派发请求，或重启恢复已明确证明未派发且消息投影无残留，才可重新排队。重试资格必须通过同一取消事务领取，只有获胜调用得到一次性证明。多个页面不能重复领取，用户取消也不能触发重试。
- 自动重试采用退避，最多连续五次。持续故障时显示原因与”再次尝试”。等待中的消息仍可编辑、撤销，新消息不越过旧队列。编辑后显式发送回到原位置。
- 自动出队遇到跨会话问询时等待其结束，不弹确认框，也不取消问询。附件缺失或无效时要求编辑，存储截断不能变成只发送正文。
- 队列显示轻量状态行，自动恢复不提供”继续发送”按钮。旧版无原因暂停保留一次确认。缺请求编号的旧存根只允许核对后保留草稿，所有引擎均不按同文历史猜测送达。

## 受理与退出

| 操作或故障 | 结果 |
| --- | --- |
| 发送回执丢失、刷新 | 按请求 ID 查询持久回执，不按忙闲或同文消息猜测。 |
| 相同请求重送 | 返回原回执，不再次切换或启动；同 ID 不同内容拒绝。 |
| 取消先于迟到 POST | 保存取消记录，迟到请求不进入引擎。 |
| Esc 后收到旧回执 | 不恢复待发送状态，不重复填入草稿。 |
| 主动退出 | 有工作或无法确认状态时提示确认，阻止新派发并取消本实例 Runner。 |
| 异常退出、重启 | 未派发请求可重新发送；终态不明则保留核验栅栏；已有来源只恢复提交。 |
| 已确认停止后的队列 | 等权威 ready 后自动续发，不与被中断回合重叠。 |
| 重启后队列 | 保留内容，重新核对回执和 ready 后自动继续；需人工处理的原因保持不变。 |

`requests/<sid>/receipts.json` 只保存请求 ID、内容指纹、受理阶段、回合关联与结果，不保存正文。阶段包括 accepted、preparing、started、finished、rejected、cancelled 和 uncertain，取消与受理通过文件事务锁排序。

原生回合仍以持久化派发闸、SourceReceipt 和 Manifest 为准。强杀不能作为完成证据。不确定的请求仅在核验提交、或用户明确”保留证据并结束本轮”成功后才放行。已执行的外部动作不伪称回滚，也不承诺工具”恰好一次执行”。

队列仍存于浏览器，页面关闭期间不会派发；本改动不等于后端持久队列迁移。现有批量合并发送语义不变。

旧草稿没有请求 ID 时明确标注未知，由用户选择保留为草稿并核对历史，不自动推断或重发。

## 历史语义

- Claude custom tool 用标准参数对象承载原始字符串，私有元数据保留来源类型、原名；Pi 使用不进入模型上下文的 custom marker。回切恢复 custom 类型，不降成 function call。
- 思考内容保留公共投影类型，不搬运其他提供方的私有 thinking 签名；工具失败保留明确失败标记。未知块、错误工具配对和不可转换的结构化结果显式拒绝，不能丢弃正文。
- 本节原修复引入 projection v2；当前新 Pi SourceReceipt 使用 v4，其他引擎使用 v2；既有来源按其回执版本及对应缺省兼容分支回读，旧导入重试保持编码。不能直接重算既有 Manifest 哈希；此前已丢失的旧投影信息不宣称自动补回。

# Pi KV 预热边界

预热是可选的端点性能优化，不是 Skill，不改变系统提示或任务推进规则。默认关闭，不能仅因配置 Ollama provider 就自动启用。

## 启用范围

必须同时设置 `PI_KV_WARMUP=1`、`PI_KV_WARM_PROVIDER=<精确 provider>`、`PI_KV_WARM_MODEL=<精确模型 ID>`。例如模型 ID 为 `qwen3.8:27b`，不带 provider 前缀。配置只放本机环境，不作为发行默认值。

Desk 构造命令与 Pi 扩展均检查范围；同一 provider 下其他模型也不会预热。仅支持 `openai-completions`，端点与鉴权来自当前模型的 Pi registry，不接受独立的全局 URL 覆盖或重定向。

## 请求与生命周期

- 仅在 `session_start` 且空闲、无排队消息时尝试；使用当前系统提示加固定占位问候，最多生成一个 token。
- 不读取会话正文，不缓存或回放请求，不读取旧 `kv-warmup-body.json`。系统提示为空或超过 64 KiB 时跳过，不截断。
- 默认总超时 5 秒，配置上限 10 秒，包含鉴权等待。超时后迟到鉴权不得发请求。
- 正式回合开始、实际模型请求、模型切换或关闭时取消预热；不在请求发送阶段补发预热。
- 同机各 Pi 进程按端点、provider、模型竞争一个固定时间窗口的尝试名额，默认 30 分钟。失败也消耗当窗名额；崩溃不会留下永久锁。窗口边界可能有相邻两次尝试，不保证滑动窗口限流。
- 本地只保留哈希命名的空目录作为名额标记；不写提示正文、鉴权或会话 ID。日志仅记录跳过原因、失败或 HTTP 状态。

客户端取消不等于服务端已停止计算；跨设备与节点 timer 不共享名额。启用前仍需验证服务端缓存收益、排队与计费，不承诺所有 API 都能提速。

## 旧实现与本次范围

本机全局 `pi-ollama-longtask` 包的技能、`progress-nudge` 和旧 `kv-warmup` 自动加载已关闭；保留压缩和缓存统计扩展。该本机设置不随仓分发，其他已安装旧包的机器需分别核对。

旧缓存不自动删除。节点 keep-warm 定时任务本次未修改，也不应视为已完成远端验证。Desk 源码修改须正常同步后生效；已运行的旧 Pi 进程不会被热替换。

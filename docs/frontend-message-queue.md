# GUI 待发消息队列

待发消息与草稿保存在浏览器，后端只负责回合互斥和发送回执。当前回合结束后，待发正文按双换行合并、附件按顺序合并，作为一个回合发送；派发时使用会话配置。

续发由整个 Desk 页面的调度器维护，不依赖当前展示哪个会话。隐藏或释放正文的会话只核对配置、回执及执行状态，不加载完整历史。SSE 收尾即时驱动续发，丢帧后由页面级轮询补核；只检查有待发消息或待确认回执的会话。关闭整个页面、系统冻结浏览器期间不保证续发，恢复页面后先核验再继续。

点击或上键取回队尾编辑，暂停其余消息，提交后放回原位置。”发送其余消息”保留输入草稿。队列 × 只删除待发项。Esc 在尚未产出且无其他待发时撤回当前输入，否则中断当前回合。未知回执、撤回未结束、编辑暂停与附件缺失都不能自动放行。

队列不设顶部操作栏。缺失附件的“补充附件”位于对应消息行；重试、旧数据确认与编辑操作跟随清单下方的状态说明，仅在需要处理时出现。编辑唯一一条消息时可“保留为草稿”退出队列编辑，不发送内容；有其余待发消息时仍可选择“发送其余消息”。

后端队列版本遗留的数据经 `queue-recovery` 单次迁回：先完整保存浏览器草稿，再确认交接，确认丢失可幂等恢复。编辑稿保留，迁回消息需确认后发送；执行结果未知的项目不重新入队。兼容接口不接收新队列任务、不调度回合，旧数据和附件保留到删除会话。

验证：`test_frontend_page_queue.py`、`test_queue_recovery.py` 及原有队列、回执、撤回专项。

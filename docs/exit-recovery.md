# Desk 退出与会话恢复

正常退出、壳崩溃、后端被杀都不能以“等待模型完成”为前提。关闭浏览器页面与退出本机 Desk 不同：前者不停止后端。

## 执行边界

- 正常退出先封闭新派发，再中断已运行回合。排队消息不自动续跑，未完成审批不自动批准。
- 普通 Pi 的回合、常驻进程及独立压缩 RPC 均纳入关停，控制命令与发送共用会话锁。协议取消不能被写满的 stdin 阻塞，超时时按本次进程组终止。
- Pi 与 Shepherd 私有原生执行增加轻量父进程看护，后端强退后终止其所属进程组。Pi 会话另用原生写者继承的文件锁，以防旧写者尚未退出时新进程写同一记录。
- 不承诺撤销已执行的外部操作，也不能凭本地断线证明远端排队或计费立即停止。原生 Writer 的所有权清理继续覆盖双重 fork 和脱离进程组后代。明确独立运行的持久 peer worker 另按回执协议管理。

计划重启由平台宿主接管，具体准入和有界停止规则见[重启协议](restart-policy.md)。用户中断的 Pi 子代理通知另受持久取消边界约束，见[子代理回投](pi-subagents.md)。

## 恢复边界

普通 Pi 沿用原生 JSONL。未提交压缩不冒充成功；已保存历史保留。旧 UI 快照收口为中断，不恢复排队、重试和压缩中的假运行状态。

普通会话（Claude、Codex、Pi）派发后若没有收到实时终态，回执先记为未知，但只在旧原生写入进程可能存活时阻止新回合。如果写入锁可以非阻塞取得，即证明旧进程已退出，此时按原生记录结案，不需要用户确认。具体判定规则为：Claude 对话记录在本轮之后以 `end_turn`/`stop_sequence` 收尾且没有未返回的工具调用时记为 completed，最后一条是 CLI 写入的 API 错误时记为 failed，其余记为 interrupted。其他引擎暂无原生取证时统一记为 interrupted。结案只写回执、推送 ready 并在状态区说明结果，不重发请求，也不改写历史。写入进程仍存活时后台退避重探约 10 分钟，仍无法证明退出才保留”保留未知边界并继续”入口。实现见 [delivery_recovery.py](../desktron/lib/engine_adapters/delivery_recovery.py)。

Shepherd 在持久派发标记前建立归档锚点。终态已归档则仅补提交；旧进程精确确认停止后，校验已记录内容，以 unknown 收口不确定结果，再建立替代 Binding，不重放工具。

启动时“旧进程还在退出”不是永久隔离：有界退避核验，用户再次操作仍可重新探测；活进程或身份不明期间不并发启动替代写者。真正的哈希损坏、来源不符仍保留证据并提供明确隔离入口，不能以可用性为由静默丢历史。

## 验证

`test_exit_reliability.py` 覆盖父进程 SIGKILL、原生写锁释放、退出拒绝迟到请求、堵塞取消管道、控制命令互斥、暂态 fence 恢复及派发窗口故障。`test_pi_exit_native.py` 使用真实 Pi 和本地模拟模型验收压缩中断后继续发送。原生测试不操作用户会话、不调用线上模型；整机断电、磁盘损坏与远端取消确认不属于已实测范围。

# 文档维护规则

文档描述可核实的当前行为。实现、设想、历史决策和环境验收分别标明，避免读者把“计划支持”当作“已经可用”。

## 两套入口

`desk-docs/00-index.md` 是随产品分发的使用手册，按用户要完成的事组织；`docs/00-index.md` 是源码仓的开发与维护入口，按模块和契约组织。使用手册不依赖被 payload 排除的开发文件才能完成基本操作。

每个主题只有一个当前正文。退役主题直接删除，并同步清理指向它的链接。

## 用 Desk 迭代 Desk 的双份交付

此场景的设计文档、调研报告及配套证据需要同时保留在两处：源码仓 `docs/` 用于版本管理、评审和后续开发；迭代工作流的 `artifacts/` 用于制品展示、阅读和查找。仅放进源码仓或仅在回复中给出文件链接，不算完成制品交付。

以仓内文档为维护源，交付或修订时同步更新制品副本及相关附件，并适配两处的文件链接。两份承担不同入口，内容保持一致，不分别演化；本约定只针对用 Desk 迭代 Desk，不要求其他工作流把普通制品写进其引用的代码仓。

## 修改时核对

1. 从入口完整走到所需文档，检查安装包中是否也存在。
2. 用源码、schema 或测试核对字段与行为；验收结果注明实际运行环境。
3. 同步入口、错误处理和数据边界，删除已退役的操作建议。
4. 检查相对链接、源码路径和必要的锚点；移动文件时保留已被代码、技能和历史记录引用的去向。
5. 不写入个人安装路径、凭证、具名判断或运行态内容。

## 核对与证据

每次变更随代码更新相关正文。过长主题按稳定职责拆分；不累积第二篇“当前方案”。

## System prompt 文档导航

`grounding/documents.py` 只把实际存在的使用手册和关联源码仓开发目录的绝对路径，经统一 grounding 系统约定注入各引擎；不解析目录中的主题列表，也不注入正文。空工作流及桌面会话同样包含导航。读取范围见 [System Prompt 装配与治理](system-prompt.md#文档读取范围)。

使用手册优先取当前工作台目录，否则使用随程序安装的手册，并输出实际绝对路径。仅在当前工作台、工作流目录或绑定仓库同时存在开发索引、`manifest.yaml` 与 `desktron/lib/grounding/builder.py` 时，附加开发入口。目录页负责供读者查找主题，主题排序不改变 Prompt 导航。

没有手册时显式提示核对安装内容，不把缺文件解释为功能不支持。导航回归覆盖三引擎、桌面／工作流、来源目录、开发范围和按需读取边界；测试入口为 `desktron/tests/test_grounding_documents.py`。实际执行结果与运行环境另行记录，不把测试存在当作测试通过。

## 界面语言

界面语言是独立模块。`app-i18n.js` 负责查找译文、参数插值、单复数、节点绑定和语言切换。译文按语言分包，`app-i18n-zh.js` 是参照包，`app-i18n-en.js` 是英文包。服务端把模块、各语言包与 `app-core.js` 合成同一个 `/app-core.js` 请求（`frontend_bundle.py`），所以其后所有脚本都能使用 `DeskI18n`，首屏请求数不变。修改这份合包清单需要重启后端才生效。只同步前端而不重启，页面会缺少语言模块。

设备偏好保存在 `cd_locale`，取值为已注册的语言代码，默认中文，未知代码回落到中文。语言包声明 `label`（语言选择器显示的名称）、`tag`（BCP 47 语言标记，用于 `html.lang`、日期格式与复数规则）和可选的 `fallback`。缺少的键先回落到 `fallback`，再回落到中文参照包。值可以是 `{one, other}` 这类复数形式，按 `count` 或 `n` 参数选择。

新增一种语言：复制 `app-i18n-en.js`，修改语言代码、`label`、`tag` 并翻译各值，再把文件名加入 `frontend_bundle.py` 中 `/app-core.js` 清单（`app-core.js` 之前）。不需要修改模块或业务代码；语言选择器自动列出已注册的语言。`test_frontend_i18n.py` 检查每个语言包的键与中文参照包一致、占位符一致。

查找方式有两种。`DeskI18n.t(key)` 按键查 `messages`，适合跨页面复用的固定说法；`DeskI18n.tx("中文原文", params)` 按原文查 `phrases`，适合整页成批接入（如设置页），中文包不必重复原文，`txh()` 返回转义后的文字。刚插入、尚未填入数据的界面模板可用 `DeskI18n.localize(root)` 按原文就地翻译文本节点与 `aria-label`、`title`、`placeholder`；它记住原文，语言切换后再调用一次即可换回，带 `translate="no"` 的子树（如终端输出）不处理。`setLocale()` 会派发 `desk-locale` 事件：设置页据此按已读取的数据重绘（未保存的输入随之清空，与重新打开设置一致），首次设置向导按已读到的状态重绘，两者都不重新检查环境或登录。`test_frontend_i18n.py` 检查源码中每个 `tx`/`txh` 原文都有各语言译文且占位符一致。

绑定规则：

- 常驻节点用 `DeskI18n.bind(node, key, params, attr, zh)` 绑定，切换语言时就地更新；支持文本及 `title`、`placeholder`、`aria-label`、`data-ph`、`data-tip`。
- 菜单、弹层等每次打开都重建的内容，生成时用 `DeskI18n.t()`，下次打开即为新语言。
- 用户内容和后端返回的文字用 `DeskI18n.plain()` 写入，先去掉同一属性上较早的绑定，避免切换语言时被覆盖。
- 按状态生成的中文文字由调用方作为 `zh` 参数传入，中文界面原样显示。
- 有些代码把固定的中文说法存进状态并据此比较（如状态行的“处理中”、模型选项的“默认”）。这类值保持中文存储，只在显示处用 `DeskI18n.label(text, prefix)` 按中文参照包反查同前缀下的键再翻译。

语言模块本身不扫描用户内容、不重建表单、不调用接口，也不触发 `_setupPaint()` 或重新打开引导；重绘由各页面监听 `desk-locale` 自行决定。新翻译进入 HTML 模板时仍需转义。单独加载某个前端脚本的测试通过 `desktron/tests/frontend_i18n_js.py` 先载入语言模块。

已接入：主导航与侧栏、设置目录与页头、AI 引擎列表、首次设置概览、全部应用页、欢迎页、左下引擎菜单、模型菜单及其子菜单、工作流与会话等右键菜单、输入框上方的任务／安排／状态栏、右侧信息卡、文件浏览器的打开按钮、设置各页与首次设置向导、系统安排卡片，以及会话过程区的状态行、步骤动词与摘要、展开详情、思考标题和子代理状态。会话正文其余提示、安排页其余部分、应用名称与简介、后端返回的文字和原生壳仍未覆盖。源码测试不代表当前安装端已生效。

## 网络与代理设置

Windows 入口接入现有设置目录、搜索、页头与 `smSection` 卡片。字段、按钮和状态行复用 `sm-field`、`sm-flabel`、`sm-input`、`sm-select`、`sm-save` 与 `sm-link-btn`，新增 CSS 只处理布局，不自建颜色或字体。实现见 `app-settings-network.js`；真实 Edge 隔离验收覆盖深浅主题计算样式、窄视口、草稿冲突与无自动重启。

仅本机同源请求可读取、保存或测试网络策略；保存采用 revision 冲突检查，错误不清空草稿。浏览器和后端分别报告加载的配置及解析摘要，避免把文件已保存误报为运行已生效。当前只开放 Windows；其他平台保持旧行为。用户说明见[网络与代理](../desk-docs/network-proxy.md)。

## 会话输入与状态

待发消息保存在浏览器，由页面级调度器跨当前选中会话维护；后端只提供回合互斥、配置核对和发送回执。取回编辑会暂停队列，未知回执、撤回未完成、附件缺失或配置变化均阻止自动续发。状态文案必须区分排队、工具执行、语义进展、软停顿、失败和终态未知，不能把连接心跳显示成工作进展。详见 [GUI 待发消息队列](frontend-message-queue.md)。

## 模型菜单分组

多个服务商的模型按服务商分组。标题仅在所属组内吸顶，滚到下一组时由下一组标题接替。点击标题或聚焦后按 Enter／空格可折叠、展开本组模型，菜单不关闭。标题只显示文字，不加箭头、底板、阴影或悬停及焦点高亮。折叠状态按执行引擎与服务商保存在当前会话视图中，关闭菜单再打开仍保留；刷新页面后重置。单一服务商保持平铺，底部引擎、Effort、压缩等参数不参与模型滚动与折叠。

模型列表与工具详情（输出、命令、原始数据、读取及改动）复用 `app-init.js` 和 `.sb-thumb` 的现有跨平台覆盖式滚动条：8px 宽、4px 圆角、透明轨道，普通色 `--shade-40`、悬停及拖动色 `--shade-55`，不占用内容宽度。模型菜单仅提高滑块层级，不再单独使用 5px 和提亮色。打开菜单、移入局部容器或滚动时显示；鼠标在列表或滑块内、拖动期间保持显示，离开且静止 800 毫秒后淡出。Windows 不再显示原生白色轨道与上下箭头；拖动滑块不关闭菜单，短内容不显示滑块，工具详情滑块遵守祖先的纵向裁剪。该基准来自 Desk 共用源码，不等同于已完成 macOS 原生 WebKit 滚动条的逐像素实机验收。

实现见 [app-chat-opts.js](../frontend/app-chat-opts.js)、[app-panel-terms.js](../frontend/app-panel-terms.js)；滚动边界、折叠与窄视口回归见 [test_frontend_model_menu_limit.py](../desktron/tests/test_frontend_model_menu_limit.py)，滚动条回归见 [test_frontend_scrollbars.py](../desktron/tests/test_frontend_scrollbars.py)。

## 全局滚动容器

滚动条不再只依赖手工选择器名单。`app-init.js` 按计算样式识别 `overflow: auto/scroll`，在初始页面、新增子树、显隐切换、悬停、滚动、聚焦和输入时接入共用覆盖式滑块；`data-desk-scrollbar` 统一关闭原生条及其宽度占位，不修改内容的 overflow、滚动位置或键盘滚动行为。动态观察只批量检查变化子树，不逐帧扫描整个文档。

范围包括侧栏、正文、工具详情、模型及其他菜单、任务/安排/状态卡片、环境详情、输入区、设置和首次设置、资源页、文件树与搜索、任务备忘、审阅/召回侧栏、审批、制品、安排结果、知识库、日志，以及代码/表格/标签栏的横向滚动。同源 iframe 继续由宿主接管原生滚动；跨域网页和原生浏览器面板不注入样式，Monaco 等组件自己的非原生滑块不改写。

纵向和横向滑块均为 8px 厚、4px 圆角，普通色 `--shade-40`、悬停/拖动色 `--shade-55`，没有白色轨道和箭头。容器悬停时保持显示，离开并静止 800ms 后淡出；短内容不显示，移除容器时回收两轴滑块。滑块遵守祖先和 iframe 的裁剪，层级取所属浮层之上。任务、安排、状态及任务详情允许拖动自己的滑块，不把它视作卡片外点击。

手机会话刻度长度缩为原来的 2/3：普通横杠从 10px 改为 `calc(20px / 3)`，命中横杠从 18px 改为 12px，粗细和纵向步距不变。正文与输入区共用左沟槽为 22px、右留白为 20px，较上一版两侧各增加 2px，聊天框总宽度缩小 4px；触屏及信息栏停用后的恢复规则沿用手机右留白，非手机保留原值。刻度列为左起 2px、宽 18px，增加 2px 左内距，使横杠距页边 4px，整列命中范围不变且不侵入正文；预览卡左缘为 22px。桌面刻度和留白不变；覆盖窄屏及粗指针横屏断点。回归见 `test_frontend_toc_fixed.py`、`test_frontend_toc_visual.py` 和 `test_frontend_mobile_chat_spacing.py`，不代表已部署或真实手机验收。

会话左侧刻度列（`.hs-toc`）不接入自绘滑块，保留原有滚动、刻度点击和 CSS 原生条隐藏。手机聊天正文（`.hs-body`）仅在用户滑动、滚轮或滚动键产生滚动时显示；聚焦输入、键盘引起的布局变化及自动贴底不会单独点亮。连续或惯性滚动延长显示，停止 800ms 后淡出；模拟悬停不阻止淡出。桌面正文保持原显隐方式。事件及 WebKit 合成回归见 `test_frontend_mobile_sidebar_scrollbar.py`，不替代真实手机软键盘验收。

手机设置页顶部导航（`.settings-center-live .sm-inner-nav`）按相同抽屉断点关闭覆盖式滑块，沿用 CSS 隐藏原生条，仍可横向滑动并选择分类；设置正文及桌面纵向导航保留原滚动条。回归见 `test_frontend_settings_nav_scrollbar.py`，不代表已部署或真实手机验收。

手机左侧菜单（`#panel-list`）是显隐规则的例外：按侧栏抽屉断点（宽度不超过 820px，或粗指针且高度不超过 520px）仅在实际滚动事件中显示，滚动停止 800ms 后淡出。打开、悬停、聚焦、内容更新和刷新通知不点亮滑块，触摸产生的模拟悬停也不阻止淡出；惯性滚动继续延长显示，鼠标拖动期间保持显示。桌面侧栏与其他菜单沿用原规则。事件回归与深浅主题、竖横屏 WebKit 合成页面验收见 `test_frontend_mobile_sidebar_scrollbar.py`；不代表真实手机验收或已部署。

`test_frontend_scrollbars.py` 的 Windows Edge 隔离用例覆盖截图中的状态详情、18 类容器、textarea、未登记的内联容器、横向拖动、深浅主题、层级、动态增长、关闭重开和回收。代码及测试均不代表已部署，也不代表完成 macOS 实机逐像素验收。

## Windows 会话阅读排版

整合远端 `6ba75b9` 时保留 Windows `1d693e8` 的字体基线：公共界面的 -50 字重调整继续用于其他平台，Windows 以 OS 作用域保留常规400／中等500令牌、原有组件显式字重及字体简写中的字重。保护规则只改字重，以 `:where(html.os-windows)` 保持原选择器特异性，不回退新图标、布局和交互。Windows 专属正文与侧栏参数仍按下文执行；静态及 Edge 合成页面回归覆盖共享菜单、设置、登录、任务、工具标题和编辑控件。

`html.os-windows` 沿用 Windows Codex 26.930.4958.0 的 Electron 字号与间距，按用户要求将 UI、正文、输入区及侧栏字重从 430 下调至 350，使常规阅读笔画略细。字重不能换算为固定 1px；不缩小字号，也不使用描边、透明度或模糊模拟。无衬线栈使用 Segoe UI 与系统中文回退，不再引用 Desk UI CJK 字重别名；禁用合成字重，强调与标题仍为 600。会话正文、用户消息与执行消息为 14px、字距 0、1.625 行高（22.75px）。段距按 MarkdownRoot 节点组合计算：基础段落下距3.5px、相邻段落14px、连续 Han 段落的前段下距4px、非段落之后的段落上距7px；标题后正文、列表和引用另设间距，末段不留尾距。CSS margin collapse仍适用，4px下距不等于两段实际只隔4px。`app-core.js::mdWithHanParagraphs` 按可见行内文本的 Han script 标记段落，主渲染器与独立执行报告渲染器共用该标记；不检查链接地址或图片alt。强调和标题为 600，标题字号 21/17.5/15.75/14px。输入区单独采用 14px/20px，而非正文行高。

侧栏按层级覆盖旧显式500与窄屏规则：导航、会话名称为13px，工作流与文件夹名称为14px，均为350字重、21px行高；导航行上下内距5px、最小高度31px。主区标题为 18px/600。代码的字体栈、字号、行高与紧凑工具区尺寸不变；没有显式字重的行内代码与工具输出会继承新的350。普通控件400、引用段落400、步骤摘要500及其他组件显式字重保留，并非全部 UI 都改为350。macOS 样式不变。静态和 Windows Edge 隔离回归见 `test_frontend_windows_typography.py`，包括计算样式、混排字形宽度、中英文在 350 与 Codex 参考 430 下的实际笔画覆盖量比较，以及取消 OS 标记后的原样恢复。测试仅在独立Edge子进程中移除已确认会阻断headless输出的 `__COMPAT_LAYER=DetectorsAppHealth`，不改宿主或系统设置；缺失DOM明确失败，不回退另一浏览器。静态资源和合成页面测试不代表正式窗口视觉验收。

热力图沿用 OpenDesk 的空格加四档绿色、明暗配色及淡描边，非零日按所选周期的四分位分档。桌面与手机均为 10px 单元、3px 间隔，月份与星期标签为 12px；相邻月标签保留后一个完整月。一年骨架、周期外淡化、日期筛选、归因和详情逻辑保留，统计接口与本地账本不变。

## 原生视图

Windows 源码采用右侧双顶栏：上层原生窗口标题区、下层 Desk 页头，左侧仍为一层通顶侧栏。新壳以 `desk-windows-chrome` 标记启用布局；原生区根据主区左缘裁剪主 WebView，保留系统窗口消息与退出保护。macOS 和旧壳布局不变；安装端画面、吸附、跨 DPI 与浏览器遮挡仍需独立验收。见 [双顶栏设计](windows-chrome-design.md)。

浏览器视图在 Swift 壳中，CSS z-index 只影响工作台 WebView 内部。设置被浏览器遮住时，同时检查前端弹窗状态和原生视图显示、挂载与恢复；提高 CSS 层级未必解决问题。Desk 只管理浏览器外壳，不再向网页注入强制深色转换。飞书 applink、客户端协议和设备证书质询属于原生壳导航与认证契约，不属于前端 CSS。

聊天滚动还受流式渲染、用户主动滚动、授权卡片高度和会话切换影响。更新 DOM 时应保留阅读位置，避免每次内容变化都滚到底部。

验证包括窄屏、长内容、搜索、来回切换、子弹窗、浏览器遮挡与聊天流式输出。依据：[视口回归](../desktron/tests/test_frontend_viewport_churn.py)、[资源弹窗检查脚本](../scripts/dev/check-resource-dialog.cjs)。历史原型不作为当前 UI 验收图。

# 上下文投递与用户原话边界

## 分层

`context_delivery.py` 是三引擎共享的实际装配边界，不以字符串分隔符解释新的用户消息。

- 用户输入：文字与图片保持原样进入原生用户帧。
- Desktron 规则：`_grounding` 保留授权、合规、表达与资料入口，进入系统或 developer 载体。
- 项目导航：`_application_context` 含完整项目模型、更新时间、检索入口与有界仓库安全摘录；每轮重算，避免切换或恢复时丢失首轮场景。
- 任务提醒：`_task_review` 只提醒查询证据，不提供操作授权。
- 引用材料：`_reference_context` 是用户明确加入的资料，不属于新的用户请求或系统政策。普通会话本轮提供有界正文，后续提供持久附件索引，按本会话上传路径读取原文；索引不随 25 轮显示截断而丢失，重启后可恢复。撤回或投递清理同步移除对应索引，缺失原件明确标为不可用。每会话最多 64 份参考附件，超过时拒绝新消息，不静默丢弃。名称、路径等索引字段同样属于低信任数据。显式分叉复制参考原件并重新绑定新会话路径，不依赖源会话存活。索引读取、合并与写回共用锁，避免并发追加恢复已撤回的登记。
- 名称：Desktron 名称仅用于内部投影和原生改名控制，不通知模型，不启动回合。
- 历史：有界回退仍是经过验证的历史输入，不是当前应用上下文，不删除其检索与证据边界。

项目导航、任务提醒与引用材料以 JSON 放入标记为低信任的 application context，尖括号转义，材料不能关闭外层边界。模型仍可能不遵守自然语言边界——这不是沙箱或授权机制，真实操作许可继续由宿主控制。

## 六种主路径

| 引擎 | 普通会话 | Shepherd unified-v1 |
| --- | --- | --- |
| Claude | append-system-prompt | 当前系统快照 |
| Codex | developerInstructions；exec 用 developer_instructions 配置 | developerInstructions |
| Pi | append-system-prompt | append-system-prompt |

普通 Codex 不再在首次用户消息里塞规则 seed，续聊同样装配当前规则。Claude unified-v1 不再追加逐回合 grounding 用户块；旧记录的身份与摘要校验继续保留。

Claude/Pi 的当前系统正文参与常驻进程指纹。正文变化时在回合开始时重建进程，不能复用忽略新规则的旧进程，也不在正在执行的回合中热改。Shepherd 工作检查点按原有模型、provider、codec 与 cwd 边界复用，不改写历史或重跑工具。

## 明确保留的兼容路径

旧 private Claude Binding 的提示快照是存储与来源校验的一部分，不能直接覆盖。它仍使用带 uuid 和摘要校验的隐藏应用上下文块；不再包含名称，也不与用户原话拼接。彻底取消该载体需要显式迁移到 unified-v1，本改动不自动迁移或解锁会话。

`SCENE_SEP`、旧 seed 识别与剥离保留为历史读取兼容，不再用于生成新用户消息。CADK 等引擎全局 hook 不由 Desk 管理，不擅自修改。

## 验证边界

`test_context_delivery.py` 覆盖六种生产装配路径、续聊、名称、换代指纹、低信任边界和旧记录读取。`test_context_delivery_native.py` 使用隔离 HOME 和本机回环模型，检查三个已安装引擎 CLI 的实际 provider 请求；不使用用户凭证或外部模型，另覆盖 Codex exec。

这些测试证明实现及隔离原生协议，不证明当前运行 Desk 已部署，也不替代真实引擎切换、压缩与用户验收。发布、同步、重启须另获授权。

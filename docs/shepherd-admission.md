# Shepherd 上下文准入与超窗恢复

三引擎共用 `context_admission.py` 进行准入与拒绝恢复。缺少兼容检查点时，容量已知且完整历史可容纳的请求保留工具结果和图片；容量未知或超过预算时使用有界历史。先核对检查点和已确认失败约束，确需读取后缀时按最多 12 回合一批投影、逐回合估算，达到预算即停止，不为决定降级而先展开全部历史。单个回合仍须完整核验，可能单独超过批次预算。降级时在常驻宿主获取和真实派发前，从已验证公共投影生成旧摘要和最多最近 12 回合的有界文本。工具参数、结果、图片和推理正文均不携带，凭证脱敏，安全说明与历史检索入口不可裁剪。Codex 使用原生摘要标记，Claude 和 Pi 使用普通历史用户消息，在派发前回读文本并核对 SHA-256。降级会淘汰旧常驻上下文。首个成功回合原子保存目标引擎的新原生 checkpoint，冷启动也可继续。原始归档保持完整，界面给出非阻断提示。

模型准入单独估算多模态内容：文本沿用 UTF-8 字节估算，经校验的图片按每张 16,384 token 预留，不将 Base64 传输字节视为文本。该额度用于本地规划，不是计费值，也不是所有模型的上界，Provider 仍执行原生准入。当前图片保持原样，归档、投影和检索继续按原始字节限制大小。Codex 的 Portable Checkpoint 接管与本轮附件兼容限制仍保留。

窗口取自模型目录或明确配置的预算，不推测模型容量。三引擎在无可用窗口时均保留原生准入，不因目录缺少窗口或默认项而拒绝普通回合；但历史传输不得超过 16,384 token，即使存在兼容原生检查点也要估算并在超限时降级。无兼容检查点的有界历史加载，以及已确认超窗后的缩减重建仍然生效。当前输入、系统提示和预留空间本身已占满预算时拒绝派发，不靠裁剪安全说明来强行执行。降级历史另有 16,384 token 的传输上限，不应把它当作未知模型窗口。

当原生请求或压缩子请求返回明确超窗错误，或原生错误字段包含 `autocompact_thrashing`／明确的压缩震荡文案，且失败终态已确认、用户没有取消时，归档原子记录减半并至多为 16,384 token 的历史预算，按引擎、请求模型、provider、cwd、codec 隔离，冷启动仍生效。正常回复、工具输出或用户文字中的错误文案不触发恢复；普通压缩失败、鉴权、额度及网络错误不归为上下文失败。新拒绝证据附带版本化原因及失败前历史估算，旧证据继续可读；证据随失败来源封存后，还须通过 Coordinator 提交及边界校验才能约束下一次准入。失败来源回读并提交后，只有尚无模型语义输出、工具执行、原生 hook 执行或授权请求的普通回合，才允许在当前调用中重建上下文、校验并重派一次，失败证据不覆盖。已执行工具、取消、终态未知及手动 `/compact` 不自动重放。手动压缩的失败记录同样约束下一次准入，进程恢复只补提交，不执行重试。原生内部恢复成功会清除临时拒绝状态；Claude 手动压缩的命令派发 success 不覆盖此前明确的 `compact_result=failed`。每次派发前保存不含正文的准入诊断，包括规划窗口、当前输入与历史估算、原检查点边界、投影回合数及降级原因；规划窗口仍可能来自显式压缩配置，不代表已验证的模型容量。

Pi 的摘要子请求也统一处理已知窗口的 provider，按共享错误分类和有界预算分段、合并，保留拆分回合与累计文件元数据。原生 Pi 仍决定压缩时机。已删除 Ollama 白名单、Ollama 单次摘要重复分支及失败即机械摘要成功的路径，鉴权、额度、网络与截断输出明确失败。此摘要保护也用于普通 Pi 会话，但公共加载与持久拒绝恢复仅属于 Shepherd。Codex 的 `serverOverloaded` 等待重试用于处理服务拥堵，不属于超窗补丁，继续保留。

# 日志体系

当前日志分布在服务进程、终端、引擎与功能记录中，没有一份自动汇总全部内容的全局追踪。排查先用时间和请求／会话标识对齐。

| 记录 | 入口与内容 | 限制 |
| --- | --- | --- |
| 服务与前端日志 | 实时日志面板；模块标签和客户端事件 | 内存缓冲有界，非永久审计 |
| 终端记录 | 操作助手和会话输出；PTY attach、命令执行及退出 | 交互记录不等同于结构化阶段 |
| 引擎历史 | 各引擎自己的 transcript 与 Desk 会话状态 | 格式、目录、保留方式因引擎而异 |
| 功能记录 | 安排运行、mailbox、App Control 操作及回执 | 各自存储和轮转，无统一保留周期 |

## 代码入口

[deskcfg.log](../desktron/lib/deskcfg.py)统一输出模块标签；[logbuf.py](../desktron/lib/logbuf.py)收集服务输出和前端日志供页面读取。Web 启动方式可写 `/tmp/desktron-web.log`，实际路径以启动器为准。

进程日志不保证经过统一脱敏，外发前需人工检查。

## 新增埋点原则

围绕动作生命周期记录开始、结束、耗时、结果与失败位置；用同一标识串起调用。不把“已发起”写成“已成功”，不以错误分类代替根因。记录失败应可见，但不能改写原业务退出码。

默认排除密码、token、认证响应、完整配置和无关正文。采集导出按明确允许的字段进行；避免为了排障扩大数据范围。

跨用户远程诊断暂未实现，日志目前需要用户主动导出提供。

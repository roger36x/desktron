# Project Shepherd

Shepherd 是隔离的多引擎 Conversation，同一时刻只有一个 Producer，通过持久化 generation 和派发栅栏串行执行。普通引擎会话不参与共享。正式入口使用统一归档（`unified-v1:`）。

旧版正式会话在启动后通过来源校验、格式预检和 Producer Fence 原地升级。升级时历史原生文件保持只读证据，不复制正文；新的同引擎 Binding 只保存统一归档游标。升级事务崩溃时留下可恢复的 pending switch，不会同时出现两个 Producer。无法验证的会话保留旧 Producer，并显示明确告警。

## 旧试用会话兼容

早期试用会话继续使用 `adp_trial_` 前缀及 `data/experiments/shepherd-unified/` 私有空间。它们与正式会话显示在同一个 Shepherd 书桌中，仍按前缀路由列表、历史、取消和删除；新会话只进入正式空间。旧试用数据不并入正式目录，也不显示额外试用标签。

## 权限、身份与恢复

三引擎继续使用现有权限桥，授权不跨会话或引擎继承。Binding ownership、session identity、codec 和哈希是硬边界，Claude 逐行 cwd 等环境属性不作为身份依据。动态 grounding 以专用 UUID 和内容哈希校验后从公共历史中移除。未知语义仍然拒绝自动接纳。

completed、failed、interrupted 三种终态需要原生确认。Pi 使用 agent_settled，Codex 使用匹配 Turn ID 的完成事件，Claude 使用 result。杀进程不算成功。取消时先发送协议命令，再按看门狗清理本次进程组。

公开 `idle/ready` 之前，先在会话锁内持久化请求回执。正常完成、失败及中断均使用同一边界。回执未知或写入失败时不发布 `ready`，查询状态也保持封锁。已提交但遗漏收口的回执可在同一进程内通过发送前、状态或回执查询补核。补核时持会话双锁，不收掉尚未关联 attempt 的新请求；诊断写盘失败不阻止清理和后续核验。

崩溃恢复只读取持久证据，不重跑工具。如果终态已归档但 receipt 尚未写入，可补全 receipt。确认旧 Writer 已停止且部分事件可校验时，保留已完成内容，未完成工具补 unknown 公共封口并隔离旧 Binding，原始事件不改写。确定性校验失败立即进入 blocked 状态，暂态错误则持久化并有界重试。无法验证时提供显式隔离出口，禁止静默遗漏。

统一归档中曾因 `native_evidence_incomplete` 阻塞的回合，可在启动或用户操作时重新核验。每个进程生命周期、每个 attempt 最多核验一次，且必须确认原 Writer 已停止，仍持会话双锁。校验成功才封口并替换 Binding；校验失败、身份未知或其他阻塞原因均继续保留栅栏。恢复成功后清除旧恢复提示。派发前的拒绝需要持久化真实原因，不能被上一轮错误覆盖。

斜杠命令由 `command_manifest` 按当前会话声明 owner、transport、历史写入与能力要求。Desk 命令优先，Shepherd 在派发前拒绝未声明的命令，普通原生模式才追加适配器发现的原生命令。

只有开头整段是命令名（`/[A-Za-z0-9_:-]+` 后接空白或结尾）才算命令，前端与后端 `command_token` 使用同一口径。单独的 `/`、`/ 文字`，以及含第二个 `/` 或 `.` 等非命令字符的路径（如 `/tmp/a.txt`）按普通正文发送。只有一段的绝对目录（如 `/tmp`、`/tmp 下有什么`）与命令形状相同，Shepherd 按命令拒绝。原生引擎同样可能把它当作技能或模板，因此也不按路径放行。回退和 Claude 子代理仍不开放；Pi 子代理见[独立契约](pi-subagents.md)。

回复操作栏支持从已完成并校验的回复创建独立 Shepherd 分支，沿用当前执行引擎、模型设置和工作流。分支仅复制到所选回复，历史以 `fork-snapshot-v1` 独立保存，与原生执行证据明确区分。新 Producer 使用全新 Binding、原生身份和请求空间，不重跑历史工具，也不继承权限。检查点仅保留分支边界内的内容，并重新锚定来源哈希。删除原会话不影响分支。如果执行、切换、恢复或来源验证尚未完成，则拒绝创建分支。

## 依赖与验证

三引擎均不以发布版本白名单准入。Codex 隔离导出协议声明并检查各自消费的接口，Claude 验证 SDK 回读及无模型请求的 CLI 初始化／中断握手，Pi 验证存储、工厂返回的会话与必要方法——实际 Host 初始化确认后才允许派发。探测使用临时 HOME 和最小环境，不带用户凭证，也不按版本或启动脚本路径缓存放行结果。

能力不满足、探测无法确认、缺依赖和超时会分别报告。运行时仍然验证身份、权限、归档与终态。上游 schema 未声明的原始输出事件由实际执行验证，缺失时不得提交空的完成回合。静态探测不是整个协议的兼容证明。安装更新沿用原生渠道，不自动降级。Desk 内部 SDK 的依赖锁用于可重复安装，不是用户 CLI 的准入白名单。持久 codec 保留原身份，不因 CLI 更新而改写历史。可用 `shepherd status` 核对当前能力结果。

统一测试入口见[开发与验证](development.md)。原生门禁使用真实 CLI／SDK 和本地假模型，覆盖三引擎切换、压缩、恢复、工具图片与来源校验，但不证明线上模型性能或当前安装是否已经生效。摘要见 [Recap](shepherd-recap.md)，测量方法见[性能记录](shepherd-performance.md)。

# Shepherd 进展、等待与超时

短进程与常驻宿主共用单调时钟，每回合重新创建预算。Codex 的 app-server 截止也不依赖可回拨的墙钟。普通执行默认在连续 15 分钟没有语义进展时显示软停顿提示，但不因此终止执行。整回合硬截止按思考强度和已核实窗口计算，默认基准 2 小时、上限 12 小时。手动压缩没有逐字输出承诺，三引擎均按本次操作的硬截止等待。

原生自动压缩不继承即将耗尽的回合截止：当前回合首次进入经验证的自动压缩时可获得一次有限储备，重复事件不续期，整轮绝对上限不超过原硬截止的两倍。Codex 只有同时携带当前 thread、turn、item 和进行中状态的压缩事件才能触发储备。Pi 和 Claude 在自动压缩期间暂停普通静默限制，压缩结束后恢复观察。

Provider 排队、限流重试和等待响应共用一次有界等待，默认最多 1 小时，且始终受当前硬截止约束。重复队列位置、stderr 和本地等待提示不会延长这条等待线，服务端实际的文本、思考或工具输出到达后才结束等待。Provider 报告的剩余读取预算只能缩短等待期限，不能续期。离开队列本身不代表模型已有进展。

## Claude 启动与首进展保护

统一存储的 Claude 在启动宿主后，bootstrap、初始化和 `prepared` 就绪等待共用不可续期的 30 秒预算。超时按未派发失败处理，不自动发送用户输入。bootstrap 与 recap 无工具支线继续使用 `settingSources:[]`，常驻、one-shot 和 legacy 主回合使用 `settingSources:['project']`，加载工作区 hooks、技能和项目说明，但不加载用户级设置。主回合同时启用 `strictMcpConfig`，不接受项目 MCP 扩展。常驻宿主键包含设置、CLAUDE.md 与技能摘要，内容变化后不复用旧宿主。Desk 注入的系统提示仍由快照管理。

macOS 主回合另有两层目录降级。Read、Write、Edit、Glob、Grep 等带显式路径的工具在 `PreToolUse` 阶段检查桌面、文稿、下载、媒体、Library、废纸篓和外置卷。非当前 cwd 的受保护路径直接返回该次工具失败，模型可在同一回合绕过、改用工作区资料或说明为何必须取得文件。普通权限回调收到受保护的 `blockedPath` 时同样直接拒绝，不向手机或桌面发一个注定无法解决的授权请求。

链接检查使用异步文件调用，并在 500 毫秒内返回整条路径的判定。超时、`EACCES`、`EIO`、链接读取失败或链接跳数耗尽均拒绝，只有 `ENOENT`／`ENOTDIR` 可按尚不存在的普通路径继续。底层文件系统调用本身不可取消，截止只保证事件循环和工具判定不继续等待。SDK 0.3.268／CLI 2.1.296 的真实回归确认：`PreToolUse` 回调超过 SDK 的 1 秒上限时工具不会执行，错误返回模型，回合继续。

Claude 主回合恢复内置 `Bash`，不再注入 MCP Bash、Seatbelt 包装器或 SDK `sandbox.enabled`。因此本机环回后端、App Control Unix socket、工作流登记仓库和 Desk 数据命令继续使用宿主的正常系统权限，Bash 仍经过 Claude 原生权限模式和项目 `PreToolUse` hooks。Claude 原生 `CLAUDE_ENV_FILE`（保留 `BASH_ENV` 兼容）只负责每次调用重置 cwd 并清除父进程的 Claude 会话身份与长期令牌，不充当文件系统沙箱。`run_in_background` 与 Monitor 仍不开放。

cwd 与工作流注册的 `repos[]`／`runtime_roots` 视为任务明确依赖：显式文件工具允许这些根的子树；任务根位于 Downloads 内也只开放该根，不开放父目录或兄弟目录。Glob 会合并 `path` 与 `pattern` 检查实际匹配范围，并在受保护根内拒绝任何含 `..` 的复杂模式，不能借 brace 或 extglob 越出已授权根。显式路径中的现有软链接会逐段解析，指向受保护目录时在执行前拒绝。目录名单由 `protected_paths.py` 统一提供。Bash 访问其他目录由 macOS TCC 决定；用户拒绝后命令错误作为工具结果返回模型。不得再把 Desktop、Documents、Downloads 等路径写入沙箱 deny 清单，否则初始化本身会反复触发 TCC。

项目来源会在后续回合执行工作区配置，因此程序化钩子拒绝 Write／Edit／MultiEdit／NotebookEdit 改写 cwd 及其上级的 `CLAUDE.md`、`CLAUDE.local.md`、`AGENTS.md`，以及项目 `.claude/CLAUDE*.md`、`.claude/settings*.json`、`.claude/skills/**`、`.claude/rules/**`；用户主目录 `.claude/CLAUDE*.md` 也按已加载指令保护。`.claude`、设置、说明、技能、规则及既有资源软链接的物理目标同样拒绝。配置资源枚举超时或不确定时，写工具失败关闭；读取和普通工作区写入不受影响。macOS 与 Windows 的比较都按默认大小写不敏感文件系统处理；Windows 只折叠 `\\?\<盘符>` 与 `\\?\UNC` 命名空间、通过 `realpath` 解析既有文件或最近既有父目录，并拒绝其他 NT 命名空间、`\\.\` 设备路径和 NTFS ADS。正常维护应修改源码仓后经批准同步，不能直接改运行工作区中会被 `sync-home` 覆盖的配置。该边界不宣称拦截 Bash 改写；常驻宿主仍用项目资源摘要避免在已观察到的资源变化后复用旧实例，进一步的载荷指纹校验另行设计。

`app-install` 必须用稳定证书签署 `io.github.desktron`，并验证指定要求不含 `cdhash`。优先使用唯一 Developer ID Application；不存在时复用或创建一次专用 Desktron 自签身份。稳定签名让 macOS 能在后续构建中复用每类“文件与文件夹”决定，但第一次访问仍可能显示系统授权窗，也不等于完全磁盘访问。

持久派发闸后、写入 `start` 前重新计时：SDK 必须在 30 秒内确认取出输入。取走后约 60 秒仍无模型进展时只显示可取消的软提示，不终止回合。连续 10 分钟未观察到上游响应、原生 `api_retry`、压缩、审批、工具或正文进展时，才按未确认回合终止。每个匹配当前派发的 `api_retry` 都会重新开始连续静默窗口。Bridge 自身最多一小时重试预算与整轮硬截止仍不可续期。init、首个本地原生事件、stderr 和重复本地阶段不算上游进展，迟到事件不能复活已到期预算。显式短测试预算仍取更小值。

真正的思考、正文、工具进展、原生压缩和 SDK 工具审批会解除 60 秒首响应提示，并从该进展点重新开始 10 分钟连续静默窗口，终态证据才关闭该窗口。SDK 工具审批与 macOS 系统目录弹窗是不同权限通路。无需开放完全磁盘访问作为运行前提，系统弹窗可以拒绝，也可以仅授权任务必需目录。

常驻 Claude 的独立 watchdog 持续覆盖整个回合硬截止，即使首进展后消费者、回调或控制管道阻塞，也不关闭保护。压缩仍采用原有一次性储备。watchdog 按预算对象隔离暖轮，过期宿主先置为不可复用，再停止精确 owned process。Desk 的外层 `Popen()` 不再直接进入任务 cwd，目标 cwd 由已启动的 `owned_process` 监督器交给 CLI，因此当 CLI 的 `chdir`／`exec`／动态加载阻塞时，启动 watchdog 已有可终止的监督器句柄。

超时时保留未确认回合和输入，停止当前精确宿主，不自动重发或伪造终态。常驻宿主关闭 stdout 但仍存活时，等待进程退出也受原预算约束，不因 EOF 而关闭截止。两种 Claude Bridge 的重试预算耗尽通知均按当前派发身份投影，诊断不改变归档哈希或恢复依据。回归：`test_shepherd_claude_dispatch.py`、`test_shepherd_resident_process.py`。

## 长任务阶段复核

统一存储的 Pi 普通回合在第 1 小时触发内部复核。每次复核 continuation 完成后，下一次复核按任务开始后的整点小时边界安排，已跨过的边界跳过，并非从完成时重新计满一小时。12 小时为不可续期的绝对上限。到点只排入 Pi 原生 `steer`，不打断正在运行的工具。只有匹配 request ID 且 `command=steer` 的成功回执，以及随后对应的 `agent_start → agent_end`，才完成本次续租。拒绝、超时或缺失回执均失败关闭，不重放用户请求。

复核提示要求模型核对近期成果、剩余步骤、预计耗时、阻碍、重复失败、范围变化与副作用风险，并在不合理时收尾或询问用户。提示以受信 runtime 中的 SHA-256 精确标记，从公共历史中移除，不依赖可伪造前缀。

其他公开引擎当前没有 Desktron 已准入并验证的同回合 live steering，因此暂不启用阶段复核，继续使用既有动态硬截止。不得用 synthetic 用户帧、重叠 turn 或终态后新回合来模拟同回合复核。

Pi Provider 通知绑定原生会话生命周期，手动压缩使用相同通知传输。重试、排队与恢复进展均可进入既有界面状态，摘要内容不伪装成助手增量。超时会停止本次宿主，但不能证明原生完成，因此不放行未确认回合、不替换检查点、不自动重放请求。预算不代替 Provider 自身的网络与请求截止。


## Claude 脚本执行边界

Shepherd 的 Claude 原生后台任务暂不开放：Bash 在当前回合内等待，`run_in_background` 和 Monitor 不可用。普通 Claude 直连适配器不受影响。不要用 shell 脱离进程绕过此边界，也不能承诺脚本完成后自动唤醒；跨回合后台任务需要独立的持久任务归属与通知准入，不能依赖可被回收的原生宿主。

冷启动可能收到旧后台任务的“未完成／已停止”通知。经验证的零回合通知 result 只保留通知来源记录，不作为当前用户请求的终态；仍须等待当前用户的原生结果。异常通知或缺少终态仍按 unknown 封锁，不自动重跑。已提交回合后的新增 SessionStore 写入会使内存缓存失效，不能静默纳入下一轮历史。

## 进展与连接分开

模型新增正文、思考和工具活动属于语义进展，stdout／stderr 管道活动、心跳和重复累计工具快照只提供连接诊断。相同工具输出通过有界指纹去重，不能反复消除软停顿。Provider 等待通知按请求身份与递增序号校验，旧请求的迟到事件不能改写新回合状态。

界面显示排队、等待或连接活动，不代表执行已完成。错误中的”最后进展””最后管道活动””Provider 最后连接数据”和”最近工具回执”分别报告观察值，未观测的字段不填零。终止前仍有进展时，也可能触发绝对上限。

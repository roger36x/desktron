# 扩展与贡献

把重复使用的工作沉淀为应用、安排或技能，先验证真实任务能完成，再考虑推广。

## 选择扩展方式

| 需求 | 使用方式 |
| --- | --- |
| 为长期项目建立上下文 | make-workspace skill |
| 创建可重复打开的工具或任务入口 | make-app skill |
| 创建手动或定时执行规则 | make-arrangement skill |
| 沉淀执行方法 | 编写并验证 SKILL.md |
| 将已验证的本地能力纳入产品 | contribute skill |

使用前读取当前安装版本的技能正文；参数和落点由技能及后端校验共同约束，不照抄历史设计中的命令。

## 应用要求

任务型应用说明由谁执行、做什么、如何执行，并按需定义参数与运行位置。本地网页应用提供可用页面。保留稳定 uid，更新已有条目，不重复注册。

每项应用按[App Control 契约](reference/app-control.md)声明 Agent 可操作程度及对应控制接口；没有接口时明确不可操作。外部写操作不能借应用包装跳过授权。凭证只保留在专用本机存储，清单使用引用或占位符。

## 贡献要求

提交前说明解决的具体问题、操作结果和验证方法。官方应用从源码构建分发，本地声明与运行数据不得混入发行包。发布使用干净快照并经过相应授权。

源码仓的开发入口为 `docs/00-index.md`；用户手册只保留执行边界，不复制开发脚本细节。

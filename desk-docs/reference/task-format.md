# 工作流与任务数据契约

工作流提供上下文，任务维护待办，会话保存执行历史。会话不绑定单个任务，也不按任务分组。导入已有会话只增加引用，不重写原始目录或 transcript。会话页任务栏展示本工作流全部开放任务，不表示当前会话已逐条关联。只有从某条任务的”新建会话”入口发起，或 Agent 以稳定任务 id 执行 claim/progress，才会在私有账本建立多对多关联，供 recap 在严格完成条件下收口。

## 工作流

[workflow/api.py](../../desktron/lib/workflow/api.py)管理 `/workbench/domains`、参考材料和仓库关系。仓库可以位于工作流目录外；当前会话 cwd 仍为工作流目录，代码按绑定仓库的绝对路径访问。Desk 不自动创建分支工作树，分支由 Agent 按任务决定。注册前校验 id 与目录，不能将展示名称当路径或分支使用。

## 任务行

`TASKS.md` 是面板与 Agent 共用的事实源。`[ ]`、`[~]`、`[x]` 分别表示待办、进行中、完成。行号从 **0** 开始。更新同时传入 `line` 和 `expect` 原标题；不匹配返回冲突，调用方重读后重试。

全局任务栏通过 `/workbench/tasks?scope=all` 聚合所有工作流，不复制到 `_desktop`。AI 使用 `desk-task create|claim|progress|block|complete|release` 维护任务；多步、跨轮、异步、受阻或产出制品的工作应建账，简短问答不建账。

建账前先 `desk-task list`，同一交付物复用已有 `t`，不要按每轮措辞重新建任务。发送最终答复前重新核对本回合实际推进的任务，显式更新结果、下一步或阻碍；只有验收已满足才 complete，未部署不能描述为已经上线。若当前会话补完了其他会话留下的部署、重启或验收，仍沿用原任务 id 更新或关闭，不能因会话不同而遗留。更新使用稳定 id；同名歧义、失效 id 必须重读，不能退化为新建。已完成任务仅由用户明确恢复为待办。

recap 只按已有任务 id 补充进度、阻碍或完成结果，不直接 create/claim。新发现事项先留在日志，由主会话核实后建账。任务详情直接展示有界账本的当前快照、完成条件和关联会话；这些字段与备忘录分区呈现，不拼接或改写备忘正文。备忘录是可选的长篇补充资料，执行历史仍属于 journal，不灌入任务详情或备忘录。

私有 sidecar `DATA_HOME/task-ledger.json` 只保存有界当前态：`done/next/blocker`、revision、关闭原因、幂等 receipt 和最近 5 个关联会话；任务与会话是多对多。执行历史属于 journal，不追加进 sidecar 或任务 memo。优先级为用户/UI > Agent 显式操作 > recap 补漏 > 旧状态；UI 修改会推进 revision，使此前的 recap 快照失效，并阻止后续普通 progress/block 覆盖用户状态。仍处于开放态的关联任务，可由更新后的 recap 凭高置信结果且无下一步、无阻碍自动关闭；用户已完成的任务绝不被 recap 复活。

行尾注释字段：

| 字段 | 语义 |
| --- | --- |
| `t` | 稳定任务 id |
| `c`、`d` | 创建、完成时间；恢复未完成会清除 d |
| `note` | 关联备忘 id |
| `flow` | 阶段及节点声明 |
| `fdone` | 已完成节点坐标，逗号分隔 |
| `nl` | 节点与任务 id 的关联，逗号分隔 |
| `fcur` | 旧阶段游标，仅兼容读取 |

## 任务证据试点

显式完成条件、结构化证据、`show/review` 与回合收尾规则见[任务证据试点](task-evidence.md)。未启用契约的任务保持上述原流程。

## 任务流坐标

v2 `flow` 用原生 `|` 分阶段、`+` 分同阶段并行节点；节点名称分别 URL 编码。阶段与节点均从 **0** 开始，坐标写成 `阶段.节点`，不是任务行号。

```text
flow:Plan|Build+Review|Ship
fdone:0.0,1.0
nl:1.0=task_a,1.1=task_b
```

该例有三阶段，第二阶段两个节点；`1.0` 对应 Build。节点名包含分隔字符时须编码。旧 v1 是整串 URL 编码的线性链，解析器继续兼容。

更改 `flow` 会清除旧 `fdone`、`nl`，因为坐标可能变化；同时传新的关联才可保留更新后的进度。设置 `nl` 后旧 `fcur` 退役。UI 勾选后续阶段节点会补齐前面阶段，直接写注释前应明确这一语义。

# 网络与代理（Windows）

在「设置 → 网络与代理」配置 Desk 的连接方式。此入口需要同时安装支持该功能的 Windows 原生壳和后端；旧壳会显示尚不支持统一配置。macOS 和 Linux 当前不开放此配置，保留原有行为。

## 连接方式

- **跟随系统**：读取 Windows 固定 HTTP 系统代理，并向浏览器与后端传递相同规则。没有固定代理时不使用应用层代理；系统 VPN／TUN 仍可能影响连接。
- **直连**：清除 Desk 子进程继承的应用层代理，并让内置浏览器不使用代理。不会关闭系统 VPN／TUN。
- **手动配置**：填写代理主机或 IP 与实际端口。使用代理客户端的 HTTP 或混合端口，例如地址 `127.0.0.1`、端口 `7890`；端口可自行更改，不是固定要求。

当前只支持无认证 HTTP 代理，不接受订阅链接、SOCKS 专用端口或含用户名／密码的地址。HTTPS 网站可以通过 HTTP 代理访问，不需要填写 HTTPS 网站地址。

绕过地址以逗号分隔，支持主机名、IP 和 `.example.com` 域名后缀。本机的 `localhost`、`127.0.0.1` 和 `::1` 始终绕过代理。系统代理包含 PAC、自动发现、`<local>` 或其他不能等价传给引擎的规则时，会明确报错，不自动改成直连；可改为手动填写 HTTP 代理地址与端口。

## 保存与生效

配置保存在 `%USERPROFILE%\.config\desktron\network.json`，不修改 Windows 系统代理、引擎登录信息或既有 `env` 文件。首次保存前，继续使用原有系统与环境设置。

保存只更新本机文件，不中断运行中的回合，也不立即改变网络。等待回合结束后，正常退出并重新打开 Desk。仅重启后端不能更新运行中的 WebView2 浏览器配置。设置页会核对浏览器与后端加载的配置；不同步时明确显示尚未完整生效。系统固定代理改变后，也需要重新打开 Desk。

保存统一配置后，它优先于旧 `env` 中的代理变量和 Pi 的 `httpProxy` 偏好；不会删除这些旧配置。自行修改的引擎插件、Git／npm 专用代理配置不在统一配置的保证范围，应另行检查是否冲突。

## 分别验证

「测试代理端口」只连接指定代理的 TCP 端口，不访问外部网页、不登录，也不发送模型请求。端口可连接不代表 HTTP 转发、网页搜索或模型调用可用。

重新打开 Desk 后，再由用户分别验证网页搜索、安装下载和所用引擎的一次请求。测试失败时不会自动重试安装、切换代理或降低 TLS 校验。

# 知识、技能与记忆

知识提供可引用材料，技能提供执行方法，记忆恢复项目背景。三者各有入口和维护方式。

## 知识与技能

「代理 → 知识库」管理知识连接。Git 知识库按注册信息维护，供各工作流使用。Desk 展示连接、版本与同步状态，原始内容仍按来源平台维护。

「代理 → 技能」查看已装技能及来源，也可以预览市场技能后安装。技能使用记录来自多个渠道，计数只覆盖实际可观察到的调用，不能把零计数解释成从未使用。

读取外部资料应先确认访问链路可用。资料没有被使用，可能是无法检索或未挂载，不能先归因为质量问题。

## 项目记忆

| 内容 | 用途 | 维护方式 |
| --- | --- | --- |
| 对话记录与 journal | 原始依据及本轮事实、纠正与阻碍 | 系统保存对话，隔离 recap 追加流水 |
| notes／项目模型 | 当前项目情况 | 记忆引擎重写 rollup-current.md |
| sealed | 仅限本机的敏感信息和禁止事项 | 通过 memory skill 维护，不分发 |

会话默认携带当前工作流完整的项目模型正文、更新时间及检索 id，不再另存或展示记忆摘要。原始对话、journal 和 sealed 不自动注入，需要原始依据时按需检索。项目模型是历史认知，不能代替实时状态核验，也不构成操作授权。

在侧栏工作流标题上点右键，选「查看记忆」，可阅读同一份项目正文，按项目概况、已定方案、长期约束和待确认问题分段；旧英文标题也按这四类展示。底部保留检索编号，不再提供独立的「会话摘要」区。这里只读，不会改写原记录。旧模型的摘要字段不再使用，由记忆引擎成功重建时移除。

项目记忆由记忆引擎定期重写，并使用 Desk 共用的表达规范。项目进展、决定和用户纠正由系统记录后更新项目模型，主会话不直接修改对话、流水或项目模型。只有需要留在本机的敏感信息或禁止事项才通过 memory skill 写入 sealed。人物关系与依赖只查图谱，不从对话或笔记推断。

需要明确留存时，让 Agent 通过 journal skill 请求 recap；当前会话不拟写流水正文。纠正 append-only 记录时追加新条目，注明被修正内容；已经撤回的判断也应保留撤回理由。

不要直接编辑记忆的物理文件，也不要复制到发行包。底层仍兼容 `sot` 中的旧 pinned／fact：已确认判断保留原优先级，未确认 judgment 不自动晋升，fact 只供知识检索；这不构成要求主会话新增 pinned 的操作入口。存量记录不因本手册收敛为三类内容而删除。

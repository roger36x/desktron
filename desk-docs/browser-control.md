# 浏览器操控与网页查证

Desk 提供两类不同能力：无登录态的公开网页查证，以及由 App Control 操作的内置浏览器。两者的身份、证据和授权边界不同，不能静默互换。

## 公开网页查证

Pi 的 `web_search` 在一次性后台匿名隔离标签中打开固定的 DuckDuckGo 搜索页，不切换用户当前页面。调用结束后立即销毁临时标签，不写入浏览器标签恢复记录。`web_fetch` 仍以受控直连 HTTP 读取用户给出的链接、搜索结果或已读取页面中的链接。两者都不携带用户 Cookie、SSO、Authorization 或浏览器身份。后台浏览器不可用时，搜索明确失败，不静默绕过。

搜索摘要只是选源线索；事实引用应来自后续抓取的原网页。内部资料、凭证、个人数据、内网地址及其他不应外发的内容不得作为公开搜索查询。`web_fetch` 需要登录、JavaScript 渲染、点击、表单或截图时，会建议改用浏览器；Agent 必须显式切换，不能自行复用用户身份。当前抓取不使用浏览器兜底，以保留逐跳公网地址与重定向校验。

Codex 和 Claude 使用各自原生的网页能力，返回格式与 Pi 的 Desk 证据 schema 不完全相同。任何引擎都应区分“搜索候选”和“已读取原文”。

## App Control 标签

Agent 自行打开网页时默认使用匿名隔离标签，不带用户 Cookie 或 SSO，也不会拉起本机客户端。需要用户登录态时使用带身份模式；首次访问该站点须由用户确认，后续只在原授权范围内复用。只有要操作用户已经打开的页面时，才需要用户把该页交给 Agent。

读取和点击不等于业务成功。动作返回后应检查页面状态、服务端回执或目标数据；固定等待时间不能替代结果验证。敏感设置、登录和授权界面受保护，脚本不能代替本人确认。

## 内置浏览器与飞书

macOS 桌面壳以 WKWebView 承载浏览器页。用户页面使用持久存储，Agent 隔离标签使用非持久存储。浏览器外壳跟随 Desk 外观，但 Desk 不再注入强制网页深色化；网页内容由站点自己的主题与 `prefers-color-scheme` 行为决定。

飞书条件访问可能要求客户端授权和设备证书。新版原生壳会把飞书 applink 改写为客户端协议并交给系统，处理 `lark://`、`feishu://`，并在用户页面收到客户端证书质询时只按服务器指定签发者从钥匙串选择有效身份。Agent 隔离标签不拉起客户端，也不出示设备证书。

这些能力依赖当前运行的原生壳，而非仅依赖后端代码。已同步源码或已重启后端，不能证明新壳已加载；遇到飞书“设备未授权”时，应先核对宿主版本、点击授权是否拉起客户端、钥匙串是否具有策略要求的证书，再判断站点权限。

## 故障定位

原生浏览器视图位于工作台 WebView 之外。设置弹窗被遮挡、网页未出现或标签无法恢复时，要同时检查前端页面状态与原生视图的显示、挂载和回收；单纯提高 CSS 层级通常无效。

浏览器登录态、站点授权和控制凭证属于本机运行数据，不进入仓库或分享材料。自定义应用能否被 Agent 操作取决于它声明的观察与操作能力，见[App Control 契约](reference/app-control.md)和[扩展与贡献](extend.md)。

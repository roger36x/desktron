# 日志与故障反馈

先保留失败现场，再判断重试方式。日志中的最后阶段和命令退出结果比单张“失败”截图更容易定位问题。

## 运行问题

实时日志面板用于查看前端及服务端事件；终端输出用于还原交互。运行日志与引擎历史是不同材料，不保证集中于同一个导出包。

反馈中注明时间、版本、操作入口、期望结果和实际结果。避免上传密码、token、完整认证响应或无关对话。

## 会话与重启

| 现象 | 先核对 |
| --- | --- |
| 长时间没有进展 | 是模型／工具新增输出，还是仅有心跳与管道活动；软停顿不代表已失败 |
| 原生压缩达到最长时限 | 压缩状态、整轮硬截止和原生终态；不能凭最近仍有输出判断未超时 |
| 终态未确认 | 最后一次工具及实际仓库／远端结果；保留原请求，不直接重发 |
| 中断后仍看到子代理记录 | 区分历史来信、取消确认中的通知与新回合；保存运行编号和发生时间 |
| 重启返回 409 | 阻断操作类型与当前生命周期状态；不要循环重启或绕过监督 |
| 重启已 accepted | 只代表已接管，仍需核对新 boot、运行版本与连接恢复 |

手机界面显示「处理中」或旧版「已接收，等待引擎响应」，不证明模型服务已收到请求。统一存储的 Claude 分别限制初始化、SDK 输入交付与首响应等待：初始化和输入交付各最多 30 秒。约 60 秒无模型进展时只显示可取消提示，连续 10 分钟没有上游响应、原生重试或其他原生进展才结束。长时间无输出请保留会话名、发生时间及超时提示，不要仅归因于 Tailscale。

macOS 目录授权窗只出现在电脑上，可以拒绝或仅允许任务必需目录，不要求完全磁盘访问。SDK 工具审批不能代替系统授权。初始化超时表示用户输入未派发；派发后超时仍须核验原生执行记录，不要直接重发。断线时按原请求回执核对，不把未知结果视为未发送。

重启状态为 `unknown` 或 `restart_error` 时保留回执和日志，先确认宿主是否接管；不要手动杀进程、清锁或反复提交。认证错误应按提示所属引擎和 Provider 检查，切换引擎不能证明旧认证已恢复。

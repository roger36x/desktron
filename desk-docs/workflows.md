# 工作流与任务

工作流保存一个项目持续需要的背景、参考材料、仓库入口和任务。会话在工作流中推进工作，长期状态由任务和记忆承接。

## 建立工作流

点击侧栏「工作流」旁的加号，输入名称后按回车创建；该菜单不提供已有目录导入。创建后填写用途并添加项目参考资料。需要处理代码时绑定已有仓库；代码仓可以位于工作流目录之外。绑定不会向外部仓库生成 Desk 脚手架。

工作流可以引用已有会话。导入会话只增加引用，不改变其原始工作目录、引擎历史或归属。涉及多个分支并行开发时，明确选择对应仓库和工作树，避免将工作流名称误当作 Git 分支。

## 任务清单

面板与 Agent 编辑的是同一份 `TASKS.md`：

| 标记 | 状态 |
| --- | --- |
| `- [ ]` | 待办 |
| `- [~]` | 进行中 |
| `- [x]` | 完成 |

任务详情优先展示任务自身的轻量状态：标题作为目标，`done/next/blocker` 分别表示已完成、下一步和阻碍；启用完成条件后还会展示验收项，已关联会话可直接打开。任务流用于拆分阶段。备忘录只作为可选的补充资料，适合保存长篇背景、方案和参考链接；没有备忘录不影响任务跟踪。

Agent 通过 `desk-task create|claim|progress|block|complete|release` 维护任务。`done/next/blocker` 各保存最多 160 字的当前快照，详细过程交给 journal。用户在界面中的修改优先；遇到 revision 冲突先重读，不覆盖。

行尾 HTML 注释保存任务 id、时间、任务流和备忘关联。保留已有字段；底层行编辑另有行号和原始标题校验。精确字段见[任务数据契约](reference/task-format.md)。

任务可显式启用[完成条件与证据](reference/task-evidence.md)：按需求列明提交、测试、部署、验收或制品。启用后不能随进展扩大完成条件；全部证据齐备且没有下一步或阻碍时，正常回合收尾可自动核对并关闭。旧任务不自动套用这项试点。

## 背景与状态

参考资料放在工作流的上下文入口，长期约束通过 memory skill 管理。自动生成的完整项目模型直接进入会话上下文，用于恢复背景，不能替代任务验收，也不能将“进行中”当成可核实的进度；说明版本、日期或已完成数量。

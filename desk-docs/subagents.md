# 子代理与结果通知

Pi 主 Agent 可以把独立的只读任务交给子代理，例如查找代码、检查改动或整理证据。它们继承父会话的模型、思考级别和工作目录；可用能力取决于本机依赖是否已准备。

## 执行与查看

同步任务在工具调用中等待结果。异步任务先返回运行编号，让主 Agent 继续独立工作。异步默认是本次主调用的必需依赖：已完成结果在安全边界进入上下文，剩余结果在主调用结束前等待并整合，不再另起通知回合。需要结果才能继续时，父 Agent 可用 `action=wait` 阻塞等待指定 `run_id`，无需反复查询。

只有明确设置 `required=false` 的独立后台任务，才保留完成后另发通知的行为。完成前审查和验收不能使用此方式。父 Agent 仍可查询状态或取消指定运行；状态查询不消费结果。详情展示排队、运行和终态；排队提示不会单独唤醒主 Agent。

当前只开放受控的只读角色和工具。子代理不能编辑文件、执行写操作或继续派生子代理，收到结果也不能视为用户批准。任务失败时保留同批其他任务的结果。

时限由 Desk 统一决定：子代理连续 5 分钟没有进展，或总共运行满 30 分钟，会被终止，不是只停止等待。排队和工具执行期间不算无进展。因无进展被终止时记为失败，并带回已有的部分结果。

## 结果来信

独立后台任务（`required=false`）的异步结果复用 `desk-msg` 的 Agent 来信样式，标题显示 Pi 子代理及完成状态。长正文默认折叠，展开后按 Markdown 阅读；单批运行编号保留在标题提示中。旧历史、实时结果和批量结果使用同一展示规则。

相近时间积压的结果可合并为一次通知。通知仍经子代理自己的持久交付队列处理；来信样式不代表它改走 `desk-msg`。通知回合不提供 `subagent` 工具，主 Agent 应整合结果并收口当前任务。

## 中断后的行为

用户中断会建立持久取消边界，请求停止在途子代理，并撤销尚未派发的结果通知。边界之前的结果即使稍后成功，也保留在子代理记录中，不再唤醒主会话。

取消仍需确认；已经开始的主回合或已经完成的操作不能靠隐藏通知撤回。若显示结果未确认，先检查原运行编号与交付状态，不重复启动同一任务。

原会话暂时切离 Pi 时，结果保留，切回后再检查是否可投递，不会直接发送到另一引擎。重启后读取原记录和回执，不重新启动历史子任务。本回合依赖绑定原主调用，不自动注入新的用户请求。交付已提出但未能证明消费的结果保留为未确认，不自动改走独立通知。通过原 `run_id` 查询，尚未交付的依赖可显式等待恢复。

其他协作方式见[会话与协作](sessions.md)，排障见[日志与故障反馈](diagnostics.md)。

# 设置与更新

设置页集中呈现本机的环境与管理入口。它与安排、应用、代理采用一致的侧栏和内容布局。

| 设置项 | 管理内容 |
| --- | --- |
| 外观与行为 | 显示和交互偏好 |
| AI 引擎 | 安装、登录、模型相关配置及状态 |
| 网络与代理 | Windows 连接方式、代理地址与端口；详见[网络与代理](network-proxy.md) |
| 浏览器操控 | 浏览器和 Agent 操作相关配置 |
| 手机连接 | 通过可信 Wi-Fi 或 Tailscale 扫码、复制链接连接 Desk |
| 工作工具 | lark-cli 等工具的安装与登录状态 |
| 系统安排 | 随 Desk 运行的后台任务及其状态 |
| 首次设置 | 重新运行环境与登录检查 |
| Token 用量 | 按日期、工作流和会话查看本机模型用量 |
| 任务统计 | 查看任务状态统计 |
| 调试 | 查看调试信息与日志入口 |

Token 用量读取各引擎返回的 Provider usage，只在本机保存数值、时间、引擎、模型及归因标识，不复制提示词、回复正文或工具参数。统计可从日期下钻到工作流、会话和具体回合；删除会话后不再展示原会话归因，保留匿名汇总，不恢复会话正文。旧记录的用量作为历史参考单列；异常值隔离，不计入可信总量。缺少输入、输出明细时显示明细覆盖率，不做估算。

Desk 的外观只控制工作台与原生窗口。内置浏览器不提供强制网页深色化开关，网页内容由站点自身决定；这避免反色破坏图片、文档和原生深色页面。

## 界面语言

可在「设置 → 外观与行为」或首次设置页头选择「简体中文 / English」。偏好仅保存在当前浏览器或设备；切换不刷新页面，不改变模型语言、用户内容、登录状态或运行任务。

当前覆盖主导航、已接入的设置与首次设置界面、操作终端和用量等页面。用户内容，以及未接入翻译的引擎或后端原始错误，保持原文；不承诺所有界面均已翻译。

## 局域网手机试用

Windows／Mac 可在「设置 → 手机连接 → 局域网连接设置」勾选「启用可信局域网入口」，选择本机私有 IPv4/前缀（例如 `192.168.1.10/24`），保存后重启 Desk。网卡检测失败时会明确提示，可手动填写；服务端验证该地址确属本机，不接受公网、环回或 Tailscale 的 100.64/10 地址。首次启用自动生成访问令牌，私人配置保存在 `~/.config/desktron/lan.json`，不要公开或写入仓库。

Desk 同时监听环回地址与所选局域网地址的 7765 端口，只接受本机与指定网段来源。原生窗口继续使用环回入口；未带正确令牌的局域网请求会被拒绝，探活除外。设置页区分已保存与实际监听状态，不自动重启或修改 Windows 防火墙；如手机无法连接，需核对可信 Wi-Fi、网络隔离与防火墙规则。

在电脑本机的「设置 → 手机连接」扫描二维码，或点击「复制连接链接」后在手机浏览器打开。二维码在本机生成，不使用外部二维码服务；二维码和链接仅在本机环回入口显示，手机端只显示连接状态。入口未开放或监听失败时不会生成连接二维码。首次访问设置 HttpOnly Cookie，再跳转到不含令牌的地址。连接页只对本机环回入口开放；其他设备不能读取令牌。HTTP 不加密，仅适合可信局域网临时试用，不做公网端口映射。显式 `DESKTRON_REMOTE_BIND=all/0.0.0.0/any` 同样必须配置访问令牌；缺少令牌时拒绝启动，不回退成无鉴权的全网卡监听。

关闭时取消勾选、保存并重启 Desk；保存停用不等于立即撤销运行中的监听。运行网段和访问令牌在后端启动时固定，保存其他入口的配置不会使已配对手机突然换令牌。网卡地址改变时，局域网监听会明确报错，本机入口仍可用；重新配置地址后再重启。手机布局、模型调用与断线恢复需要实机验收。

旧 `DESKTRON_REMOTE_BIND=lan:<私有IPv4>/<前缀>` 环境变量仍有效且优先，设置页对此只读。旧访问令牌仍取自 `~/.config/desktron/env` 的 `DESKTRON_REMOTE_TOKEN`；请勿公开。旧方式关闭时改为 `loopback` 并重启。

## Tailscale 手机连接（HTTPS）

Windows／Mac 电脑与手机都需安装 Tailscale 并登录同一账号。Desk 不安装 Tailscale，也不自动修改它的 Serve 配置。

1. 在电脑本机打开「设置 → 手机连接」，勾选「启用 Tailscale 专用入口」，保持默认本机转发端口 `7766`，然后保存。端口须为 1024–65535，不能与 Desk 本机端口相同。
2. 按正常重启流程重启 Desk。保存本身不重启，不启动新监听；界面区分已保存配置与实际监听状态。首次启用自动生成私人访问令牌，保存在用户目录 `~/.config/desktron/tailscale.json`，不会显示在设置保存响应中。专用入口只监听 `127.0.0.1`，不会因为生成令牌自动开放局域网。
3. 在本机终端执行 `tailscale serve --bg http://127.0.0.1:7766`。Windows 设置页提供带 CLI 完整路径的 PowerShell 命令，支持已安装但 PATH 未生效的情况。若域名或端口已有其他 Serve 服务，先核对配置，不要直接覆盖。
4. 点击「刷新状态」，扫描「Tailscale 连接（HTTPS）」二维码。未安装、未登录、Serve 未指向 Desk或状态读取失败都会明确提示；不会把读取失败伪装成未配置。

已有 `DESKTRON_SERVE_PORT` 环境变量或 `~/.config/desktron/env` 配置继续有效；设置页标明其为外部管理，不覆盖旧值。主入口显式配置为全网卡监听时，需先人工调整为 `loopback` 才能使用此面板。

经 Serve 转发的请求在 Desk 看来来自本机，所以这个入口不按本机来源放行：业务请求必须带访问令牌，只有身份探针和主屏图标保留公开读取例外；未配置令牌时拒绝启动该入口。首次扫码后写入带 `Secure` 标记的 HttpOnly Cookie，此后直接打开地址即可；在手机浏览器中可添加到主屏幕。部署脚本专用的本机判定和连接页凭据也不对该入口开放。

设置页只有在对应端口配置 HTTPS 监听并转发到 Desk 时才生成连接链接；缺少监听或使用 HTTP 时显示尚未配置。二维码组件加载失败会明确报错，复制链接不依赖二维码加载。

只使用 `tailscale serve`，不要使用 `tailscale funnel`：后者会公开到互联网。检测到配置中的 Funnel 后，Desk 拒绝生成配对链接，并提示先关闭公网入口；这不代替 Tailscale 自身访问控制与网络验收。电脑休眠后手机无法连接。

关闭时取消勾选、保存并重启 Desk；保存停用不会立即撤销运行中的入口或令牌，旧环境变量方式须移除 `DESKTRON_SERVE_PORT` 再重启。Desk 不执行全局 `tailscale serve reset`，避免清除其他服务。二维码、复制链接及手机实际访问仍需在目标设备验收。

## 更新与生效

macOS 发行版可以在设置页检查、下载并安装更新。macOS 应用内更新确认安装后，先准备新版本，再由原生宿主停止当前后端并切换 payload 与桌面应用；新版本启动校验失败时自动恢复旧版。准备阶段发现不可中断的外部写操作时不会开始更新。

Windows 当前不支持应用内更新，须退出应用后运行新版安装包；见[首次设置](first-run.md#windows)。该安装流程不具有上述 macOS 宿主持有的完整更新与启动失败回滚保证。

源码开发环境显示“开发版 · 源码同步”，不下载或安装发行包。设置项的提示会同时显示载荷与宿主版本；两者不一致表示代码与桌面壳没有一起生效，需要按开发同步流程处理。

前端资源刷新和后端进程重启不是同一操作。修改后是否需要重启取决于改动所在层；代码已同步，也不能据此认定运行中的 Python 或原生壳已加载新版本。

普通重启只换代后端，由 macOS／Windows 原生 Supervisor 或 Linux systemd 监督，不等待所有会话自然完成。历史按持久记录恢复，未确认的工具不会自动重跑；仍在进行的外部写操作可能阻止重启。

重启会中断进程中的终端与 Agent。协作环境先盘点共享树，再在明确授权后同步和重启。产品发布、运行代码同步、用户数据同步也分别处理，不能互相代替。

问题反馈应同时给出安装版本和故障时间，见[日志与故障反馈](diagnostics.md)。
